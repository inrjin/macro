# 선점 실패 처리 재확인 및 v0.2 변경

원본 PE 내장 AutoHotkey 스크립트 648행 전체를 재확인했다. 선점 실패 알림의 의미를 판별하거나, 실패 좌석을 제외하고 성공을 확정하는 분기는 없다. PixelSearch 반복에서 좌석과 완료 좌표를 클릭하고 500ms 뒤 Enter를 보내는 처리다. 반복 자체가 재탐색으로 보일 수 있지만 서버의 실패 원인을 확인한 재시도가 아니다.

- 원본 내장 스크립트: `/Users/inrjin/macro-analysis-6sf_jdqo/embedded-script.ahk.txt`
- F1: 105~194행, F2: 195~262행
- `Sleep, 500`: 134, 150, 168, 188, 215, 244행 부근
- 뒤따르는 Enter: 135, 151, 169, 189, 216, 245행 부근
- PE 리소스 REA Evidence: `ev_17a92aba76babe3d5e1848bca3f125a48ce4f67a6e4891e891d847aaec0db467`
- 리소스 `>AHK WITH ICON<`, 오프셋 960112, 길이 17959. 원본 상세 해시와 보존 파일은 최초 분석 폴더에 있다.

NOL 공개 상품 HTML에서 참조된 JS 23개와 핵심 번들의 REA 분석 기록도 확인했다. 확보 범위에서 ‘이미 선택된 좌석’에 해당하는 좌석 선점 응답 처리는 확인하지 못했다. 이는 로그인 이후 로드되는 좌석 앱 전체에 없다는 뜻이 아니다. 실제 좌석 화면·경합 실패 문구·성공 응답 UI는 관측하지 못했다. 공개 상품의 약관성 안내에서 선택 좌석이 결제 중 유지된다는 설명은 실제 런타임 오류 처리 증거가 아니다.

핵심 JS REA Evidence: `ev_3ed49720e8ddc7c4c913db9652d147792d86249ecfc3ba60b0358312570977cf`. semantic 분석 한도와 23개 확보 파일 범위는 `nol-static-findings.md` 참조.

v0.2는 새로 작성한 브라우저 엔진이다. 확실한 실패 알림만 닫고 다음 후보로 이동하며 한 실행에서 실패 후보를 다시 시도하지 않는다. DOM 요소 또는 화면 픽셀 영역으로 후보를 미리 준비한다. 실제 성공 요소가 보여야 후속 클릭을 진행한다. 결과가 없거나 모르는 안내가 나타나면 중지한다. 원본 Enter 입력과 500ms 대기를 그대로 재사용하지 않았다.

실측은 로컬 연습 화면에 한정한다. `verification/seat-benchmark.json`의 화면 안내창 중앙값 3.9ms, 브라우저 alert 11.8ms는 NOL 서버 좌석 확보 시간이 아니다. 최악값은 각각 15.3ms/108.6ms여서 모든 경합에서 10ms 이내라는 주장은 성립하지 않는다. Windows 실행 및 실제 사이트의 후속 단계 자동 진행은 추가 검증이 필요하다.
