# NOL Ticket Assistant 0.2.0

Mac용 네이티브 앱과 Windows용 배포본을 분리했습니다. 좌석 경합 처리 엔진은 양쪽에서 Chrome/Edge 확장으로 실행하며, Mac에서는 SwiftUI `.app`이 설정·좌표 채집·시작·중지·기록을 관리합니다. 원본 통합매크로 EXE/ZIP은 변경하지 않았습니다.

**현재 범위:** 로컬 연습 화면과 네이티브 연결 모듈의 검증을 마친 시험판입니다. 실제 NOL 로그인 이후 좌석 화면의 선택자·실패 문구·성공 표식은 아직 확보되지 않았습니다. NOL 실전 기본 프로필은 비워 두었습니다. URL 하나만 넣으면 실전 예매까지 완료되는 상태는 아닙니다.

기존 v0.1 확장이 있다면 실행을 중지하고 비활성화한 뒤 새 버전을 설치하세요. Windows AHK와 브라우저 좌석 엔진을 같은 화면에서 동시에 실행하지 마세요.

## Mac

macOS 13 이상, Chrome 또는 Edge. Apple Silicon과 Intel 공용 바이너리이며 이 Mac의 Apple Silicon에서 실행/자가검증했습니다. Intel에서는 빌드만 확인했습니다. Mac 창 자동검사 도구는 응답 시간 초과로 UI 조작 검증을 완료하지 못했습니다.

1. `NOL Ticket Assistant.app`을 계속 사용할 위치(예: 응용 프로그램)에 옮긴 후 실행합니다. 앱 위치를 바꾸면 브라우저 연결을 다시 등록해야 합니다.
2. 앱의 **연결 · 기록 → 확장 프로그램 폴더 열기**를 누릅니다. Chrome의 `chrome://extensions` 또는 Edge의 `edge://extensions`에서 개발자 모드 → **압축해제된 확장 프로그램을 로드** → 방금 열린 `extension` 폴더를 선택합니다. 폴더는 앱 내부 `Contents/Resources/extension`에 있습니다.
3. 확장의 32자리 ID를 앱에 붙여 넣고 **이 브라우저에 연결 등록**을 누릅니다. 확장을 새로고침하거나 확장 팝업에서 **Mac 앱 연결**을 누릅니다. 앱 상단의 연결 상태를 확인합니다. 하나의 브라우저 프로필에만 연결하세요.
4. 로컬 연습을 위해 확장 세부정보에서 **파일 URL에 대한 액세스 허용**을 켭니다. 앱에서 **연습 프로필 불러오기**, **경쟁 좌석 연습 페이지 열기**, **좌석 시도 시작** 순서로 확인합니다. 처음 3개 후보가 실패하고 다음 후보의 성공을 확인한 뒤 추가 클릭 1·2를 수행합니다.
5. 실제 화면을 관측한 뒤 **좌석 조건 / 후속 클릭**을 설정합니다. 좌표는 OS 화면 좌표가 아닌 브라우저 뷰포트의 CSS 픽셀입니다. 화면 녹화·손쉬운 사용 권한은 사용하지 않습니다.

앱 연결 등록은 현재 사용자 영역에 한정되며 기존 등록 파일을 백업합니다. 앱은 로컬 ad-hoc 서명이며 Apple 공증/Developer ID 서명은 없습니다. 다른 Mac에서 Gatekeeper의 최초 실행 확인이 필요할 수 있습니다. 자세한 파일 위치와 재빌드는 `macos/README.md`를 참고하세요.

## Windows

Windows 10/11 x64, Chrome 또는 Edge 대상입니다. 이 제작 환경은 Mac이므로 실제 Windows 실행 결과는 아직 없습니다.

1. ZIP 전체를 계속 사용할 폴더에 압축 해제합니다.
2. `chrome://extensions` 또는 `edge://extensions`의 개발자 모드에서 **압축해제된 확장 프로그램을 로드** → `extension`을 선택합니다.
3. 확장 세부정보에서 **파일 URL에 대한 액세스 허용**을 켠 뒤 `rehearsal-competition.html`을 엽니다.
4. 확장 팝업의 **연습 프로필 불러오기 → 현재 좌석 탭에서 시작**으로 연습합니다. 경합 처리에는 별도 AutoHotkey 설치나 Windows 브리지가 필요하지 않습니다.
5. Windows GUI 좌표 매크로는 `windows/Start-Macro.cmd`로 별도 실행합니다. 동봉 공식 AutoHotkey 런타임으로 실행되며, 추가 클릭 설정과 원본 INI 읽기를 제공합니다. 사용 전 `windows/Self-Test.cmd`를 실행하세요. 이 AHK 모드는 실패 메시지를 읽는 새 경합 엔진과 별개입니다. 자세한 설명은 `Windows-AHK-설명.md`에 있습니다.

## 예매 시작 감지

상품 URL과 공지된 한국시간 판매 시각을 입력하고, 실제 예매 영역의 버튼을 지정해 감시를 시작합니다. 로그인·날짜/회차·대기열·보안 확인은 사이트 흐름에서 직접 진행합니다. 상품 상단의 `예매하기`는 예약 영역으로 스크롤만 하는 버튼일 수 있습니다. 기본 대상은 `#booking-aside-container button` 중 글자가 정확히 `예매하기`인 요소입니다.

좌석 지도 로딩이 끝난 뒤에만 생기는 준비 요소의 URL/CSS를 지정하면 좌석 엔진을 자동 연결할 수 있습니다. Mac 앱의 선택 항목 또는 확장의 **브라우저 좌석 엔진**을 사용합니다. 프레임/팝업이 달라지는 실제 경로는 사전 보정이 필요합니다.

서버 `Date` 헤더는 초 단위이고 CDN 시간일 수 있어 참고용입니다. 판매 실행 시각을 이 값으로 자동 보정하지 않습니다. 시각 조건 이후 버튼의 표시·활성 상태도 확인하지만, NOL의 활성 버튼 자체가 판매 개시를 보장하지는 않습니다.

## 좌석 경합 프로필

- `mode: dom`: 최상위 문서의 `candidateSelector`로 후보를 한 번 준비합니다. 각 후보가 여전히 연결·표시·활성·가림 없음 상태인지 확인하고 실제 브라우저 입력을 보냅니다. iframe 좌석은 픽셀 모드로 지정할 수 있습니다.
- `mode: pixels`: 지정한 화면 사각형 `roi`에서 `#RRGGBB` 색의 연결된 영역을 좌석 후보로 묶습니다. 탐색 범위 최대 200만 CSS 픽셀. 시작 때 후보를 준비하므로 나중에 새로 생긴 빈자리는 새 실행에서 탐색해야 합니다.
- `alertText`: 실제로 확인한 선점 실패 alert의 **정확한 전체 문구**입니다. 이 alert만 닫고 다음 후보로 넘어갑니다.
- 화면 안내창이면 `conflictSelector`, `conflictText`, `dismiss`를 함께 지정합니다. 문구가 다르거나 결과가 없으면 중지합니다.
- `successSelector`와 선택적 `successText`는 서버 응답 이후의 실제 성공 표식을 가리켜야 합니다. 좌석의 색상 변화만 지정하면 서버 확보 증거가 될 수 없습니다.
- 결과 요소가 iframe 안에 있으면 `outcomeFrameUrl`에 그 프레임 URL을 넣습니다. 클릭 좌표와 CSS 클릭 단계는 최상위 뷰포트 기준입니다. iframe 버튼은 화면 좌표로 지정합니다.
- `commit`: 좌석 클릭 뒤 선택 완료 버튼을 눌러야 결과가 나올 때 지정합니다.
- `after`: 성공을 확인한 뒤 한 번씩 누를 추가 버튼/좌표 목록입니다. 최대 20개, `delayMs` 0~30000. Mac 앱에서 사용 여부·순서·삭제를 편집할 수 있습니다. 다음 버튼이 아직 없거나 비활성일 때는 중지하므로 필요한 로딩 대기를 지정하세요.

한 실행은 한 좌석의 성공을 목표로 하며 후보 최대 100회입니다. 실패 후보는 같은 실행에서 다시 누르지 않습니다. 응답 제한을 넘으면 결과를 추측하지 않고 중지합니다. 자동 Enter·무한 반복·직접 예매 API 호출은 없습니다. 결제는 직접 확인하세요.

브라우저 작업 중지는 **Alt+Shift+S** 또는 확장의 중지 버튼입니다. Mac 앱에서도 중지할 수 있습니다. 별도 Windows AHK 매크로는 **F3**입니다. 스크롤·줌·창 크기·탭 포커스를 유지하세요. 좌표 지정 후 화면 배치가 달라지면 다시 지정해야 합니다.

## 측정 및 확인 범위

`verification/seat-benchmark.json`: macOS의 headless Chrome, 외부 HTTP를 차단한 로컬 모의 화면. 같은 페이지의 `performance.now()`로 실패 안내 발생부터 **다음 실제 좌석 click**까지 측정했습니다. 이전 요청의 모의 서버 응답 대기는 제외하고 안내 닫기는 포함합니다.

| 실패 안내 | 표본 | 중앙값 | 95백분위 | 최대 |
|---|---:|---:|---:|---:|
| 화면 안내창 | 108 | 3.9ms | 5.0ms | 15.3ms |
| 브라우저 alert | 108 | 11.8ms | 23.0ms | 108.6ms |

이는 해당 실행의 로컬 반응 시간입니다. **10ms 이내 보장 또는 NOL 서버에서 10ms 내 좌석 확보를 의미하지 않습니다.** Windows·사용자 브라우저·실제 NOL 지연은 미측정입니다. 앱과 브라우저 사이의 100ms 명령 전달 주기는 수동 시작에만 적용되고, 좌석 재시도와 설정된 예매 자동 시작은 브라우저 내부에서 수행됩니다.

검증 기록: Node 16개, 기존 브라우저 DOM 4개, 기존 MV3 통합 2개, 새 좌석 MV3 시나리오 8개와 추가 반복 측정, Mac host의 실제 프레이밍/명령/상태/재실행 방지 8개, Mac 앱·host 공용 자가검사. Windows AHK/브리지 런타임과 실제 NOL 예매는 미검증입니다.

분석: `evidence/nol-static-findings.md`, `evidence/seat-conflict-review.md`. 개발 검사: `npm test`, `npm run test:browser`, `npm run test:extension`, `npm run test:seats`, `python3 tests/mac-host.test.py`. 브라우저 검사는 Playwright Core와 Chromium이 필요합니다. Mac 앱 재빌드는 `macos/build.sh`입니다.

이 Mac 배포본의 개발 소스는 `source` 폴더에 있습니다. 개발 명령은 그 폴더를 기준으로 실행하세요. Mac 연결 설명은 `Mac-설치안내.md`에 있습니다.
