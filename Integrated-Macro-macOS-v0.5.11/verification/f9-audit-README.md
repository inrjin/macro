# F9 전체 상태 전환 검토

2026-10-22 사용자 요청에 따라 F9의 남은 실행 단계 제한을 제거했습니다.
최종 전체 검사·앱 빌드·서명·ZIP 결과는 [0.5.11 배포 기록](../release-0.5.11/README.md)에 연결합니다.

## 동작 계약

F9는 사용자가 수동 진입·캡챠를 마쳤다는 명시적인 신호입니다. Idle·Stopped·Faulted·예약 대기·진입 중·캡챠·구역·좌석·완료와 일시정지 상태에서 사용할 수 있습니다.
이전 미전달 입력을 취소하고 날짜·회차·입장 버튼을 재생하지 않습니다. 유지 좌석과 미해결 오류가 없으면 구역 우선 ON일 때 구역, OFF일 때 좌석 관측으로 시작합니다.
같은 문맥의 전달 좌석 기록은 유지하며, 이미 알려진 미해결 오류창이 있으면 그 처리부터 이어갑니다.

F9는 사이트 화면의 의미를 자동 분류하는 기능이 아닙니다. 연결된 창·권한·색상·탐색 범위·배율 가드는 유지합니다.
일시적인 가림·캡처 지연은 기존 자동 복귀 경로를 사용하며, 복귀해도 이전 입장 클릭으로 돌아가지 않습니다.
새 F4·F1·F2·F5·F8 등 후속 명령은 지연된 F9를 무효화합니다. F4 뒤 새로 누른 F9는 별도의 재시도입니다.

## 교차 검토와 교정

- 기존 Engine 단계 제한과 런타임 실행 시작 시각 제한을 확인하고 제거했습니다. 독립 초기 5개 실패를 보존했습니다.
- 다른 창을 연결했는데 이전 창의 선택 이력이 남는 경로를 수정했습니다. ID/PID가 달라지면 탐색 문맥과 수량 증거를 초기화합니다.
- Esc 전달 실패 뒤 Faulted에서 재시도하면 오류창 처리를 잃는 사례와, legacy 확정 실패 좌석을 유지 좌석으로 승격하는 사례를 실제 Engine 검사로 재현하고 교정했습니다.
- F4가 미해결 오류창 기록을 지우던 후속 결함은 배포 차단으로 판정했습니다. 최초 전체 검사에 통과한 후보도 배포하지 않고 [예비 기록](../release-0.5.11/preliminary-stop-conflict/status.json)에 보존했습니다.
- 최종 Stop 경로는 미전달 큐 취소 → 알려진 오류 문맥 저장 → 입력 중지 순서입니다. visual/legacy × queued/failed/delivered Esc의 6조건, 반복 F4, 이미 닫힌 화면, 일반 중지를 대조했습니다. 성공한 Esc는 재전송하지 않습니다.
- 같은 창 재연결로 화면 번호가 0부터 시작하는 경우 비교 순서만 재설정합니다. 원래 기준 픽셀·오류 대상은 보존하며 이전 100 → 새 1/2 화면의 복원을 검사했습니다.
- F8 캡처와 저장 사이에 새 F9/F4가 도착하는 경로에는 저장 직전 소유권 재검사를 추가했습니다.

[독립 검토](independent/review.md), [반대 검토](adversarial/README.md)에 반례·수정·한계를 기록했습니다.
최종 소스 해시는 [독립 검토](independent/source-reviewed.json), [반대 검토](adversarial/source-final-review.json) 및 `final-manifest.json`으로 연결합니다.
직전 [실행 명령 감사](../reentrant-commands/README.md)는 변경하지 않았으며 이번 작업을 시작할 때의 baseline과 소스 해시가 같습니다.

## 검사 범위와 남은 한계

독립 Engine 25개와 실제 DOM/지연 IPC 19개는 전체 검사에 포함되는 부분 집합입니다. 후속 Desktop 132개는 실제 공유 helper·Engine·VisualRecovery 검사이며, 전체 Worker나 실제 OS 입력을 실행한 검사는 아닙니다.
최종 전체 검사에서는 이 소스를 다시 검사하고 빌드 전후 해시를 비교합니다.

실제 앱 실행·물리 F9·브라우저 캡처·로그인 사이트·Windows·전체 반응 시간은 미검증입니다.
영상의 변화·복원은 휴리스틱이며 서버 선점 성공 증명이 아닙니다. 지원하지 않는 좌석/수량 표시에서는 보류가 남을 수 있습니다.
이미 OS에 전달한 입력과 이미 시작된 저장 commit은 철회하지 않습니다. 네이티브 bind 실패로 연결 자체가 사라지면 다음 연결은 새 문맥으로 초기화하며, 모든 재연결 후 기록 보존을 보장하지 않습니다.
시각 기준 없이 수동으로 확인한 legacy 오류창은 기존 닫힘 직접 확인이 필요할 수 있습니다.
