# 통합 매크로 0.5.11 — F9 직접 진행과 실행 명령 재시도

## 이후 소스 교정 — 검색 조건 변경 후 재시작 (미배포)

같은 예매창·화면 크기·배율에서 탐색 범위, 색상, 허용 오차와 크기 필터를 수정한 뒤에도
과거 설정과의 비교에 묶여 F2/F5/F9 재시도가 막히는 경로를 교정합니다. 이미 전달한 좌석의 위치·선택·실패 기록은 보존하고 현재 화면을 다시 관측합니다.
창·배율이나 수량/외곽 판정 정책이 달라 보류하면 실제 차이를 표시합니다.
검토·검사 범위는 [검색 조건 재시도 검토](verification/calibration-retry/README.md)에 기록하며, 기존 0.5.11 앱·ZIP에는 이 소스 교정이 포함되지 않습니다.

## 0.5.11 동작과 배포 검증 — 모든 실행 단계에서 F9

F9는 사용자가 수동 진입·캡챠를 끝냈다는 직접 명령입니다. 실행 대기·중지·예약 대기·진입 중에도
기존 미전달 작업과 입장 버튼 순서를 취소하고 구역·좌석 탐색으로 넘어갑니다. 이전 실행이 없다는 이유로 거절하지 않습니다.
구역 자동 선택 ON이면 구역부터, OFF면 좌석부터 시작하며, 전달된 좌석 기록이 있으면 현재 영역에서 부족분을 탐색합니다.
예매창 연결·권한·색상·탐색 범위와 실제 입력 가드는 필요합니다. 모든 사이트의 현재 화면을 자동 분류하는 기능은 아닙니다.

F2·F5·시작 버튼 재시도와 기본 OFF인 **날짜·회차·예매 버튼 직접 진행**도 포함합니다.
0.5.10까지의 배포물은 보존하며, [F9 최종 검토](verification/f9-any-state/README.md)와
[0.5.11 배포 기록](verification/release-0.5.11/README.md)에 검사·빌드 결과를 기록합니다.
실제 사이트의 입력·좌석 확보 검증과 로컬 빌드·서명 검사는 구분하며, 실행한 검사 범위를 배포 기록에 명시합니다.

## 이전 소스 검토 기록 — 수동 진입과 실행 명령 재시도 (당시 미배포)

추가 기능의 **날짜·회차·예매 버튼 직접 진행**은 기본 OFF입니다. ON이면 최초 예약 예매 버튼은
기존 설정대로 클릭하고 등록된 날짜·회차·다음 버튼은 건너뜁니다. 저장한 좌표는 지우지 않습니다.
직접 진입한 뒤 NOL 캡챠 판단·캡챠 Enter 또는 F9로 구역·좌석 탐색을 시작합니다.

F1·F2·F5와 화면의 시작 버튼은 실행 중에도 새 실행을 요청할 수 있습니다. 최신 명령이 이전 작업의
미전달 입력을 취소하며, 이전 실행의 지연된 응답·설정창 표시·좌석 관측을 새 실행에 적용하지 않습니다.
F9는 입장 버튼을 다시 누르지 않고 구역·좌석 단계를 재시도합니다. 이미 구역 안의 좌석 화면이면 F5를 사용하세요.
같은 연결 창·좌석 설정의 재시도는 전달된 좌석과 실패 이력을 유지하고 현재 화면을 다시 관측합니다.
F1은 새 입장 실행이며, 화면·설정이 달라 기존 선택 기록을 사용할 수 없을 때에는 이유를 표시합니다.
새 실행 버튼을 눌러도 이미 OS에 전달된 클릭을 되돌릴 수는 없습니다.

이 수정은 기존 0.5.10 배포 앱·ZIP에 포함되지 않습니다. [재현·상호 검토 기록](verification/reentrant-commands/README.md)에
현재 소스의 검사 범위와 남은 한계를 기록합니다.

## 이전 0.5.10 배포 준비 기록

검증한 현재 소스를 0.5.10으로 패키징합니다. **좌석 외곽으로 구분**, **NOL 선택 좌석 수 확인**,
**연석 우선**은 모두 기본 OFF이며 저장된 옵션을 자동으로 켜지 않습니다.
아래 검토 기록의 ‘당시 미배포’는 각 감사 시점의 상태입니다. 기존 0.5.9 앱·ZIP은 보존합니다.

이 문서 갱신 시점에는 0.5.10 빌드·서명·패키지 검사가 완료되지 않았습니다.
진행 결과와 버전 변경 근거는 [0.5.10 배포 검증](verification/release-0.5.10/)에 기록합니다.
검증은 공유 Rust 영상 분석, 상태 전이, UI 회귀 및 제공 이미지 확인 범위이며,
실제 사이트의 좌석 확보·결제 성공, Windows 실행, 전체 예매 지연을 보장하지 않습니다.

## 현재 검증 소스 — 좌석 외곽과 사이트 선택 수

추가 기능에 아래 두 옵션을 기본 OFF로 추가했습니다. 이전 0.5.9 앱·ZIP에는 포함되지 않습니다.

- **좌석 외곽으로 구분**: 같은 화면에 반복되는 전체 외곽을 학습해 원형·사각형·타원·마름모·회전한 좌석을 구분합니다.
  한 좌석 안의 색 조각은 같은 객체로 처리하고, 얇은 색 연결로 붙은 좌석은 독립된 외곽 근거로 분리합니다.
  중복 방지와 연석 판단에도 실제 외곽을 사용해, 외접 사각형의 빈 모서리 때문에 옆자리를 같은 좌석으로 제외하는 문제를 줄입니다.
  사용 가능한 좌석의 내부 색을 등록하세요. 배경과 구분되는 같은 외곽이 최소 6개 필요하며,
  가용 좌석만 있는 화면에서도 학습합니다. 큰 좌석 하나와 작은 여러 좌석으로 동시에 해석되는 영역은 보류합니다.
  클릭 직전에 외곽을 확인하고, 탐색 영역의 화면 내용이나 인식 설정이 바뀌면 최신 화면을 한 번 재분석합니다.
  OFF일 때 기존 색상 탐색을 사용합니다.
- **NOL 선택 좌석 수 확인**: 화면 전체에서 `선택 좌석` 문구와 수량을 찾습니다.
  오른쪽 패널 같은 절대 위치를 지정하지 않습니다. 클릭 전달 횟수 대신 사이트 표시가 한 석 늘어난 뒤
  다음 클릭을 허용하며, 목표 수량을 확인해야 선택 완료를 누릅니다. 읽기 실패를 0석으로 처리하지 않습니다.

수량 옵션은 확인 가능한 글꼴·구성만 지원합니다. 숫자 없는 0석 화면은 별도 패널 안의 제목,
`선택된 좌석이 없습니다.` 문구, `선택 완료` 버튼이 함께 확인되어야 합니다.
숫자가 그대로이거나 줄거나 예상보다 많이 늘면 추가 클릭을 보류하고 재관측합니다.
실패 원인이 모호한 상태에서 같은 자리를 다시 클릭해 선택을 취소하지 않기 위한 제한입니다.
이 옵션을 켠 상태에서 직접 선택·해제하면 기대 수량과 달라져 대기가 지속될 수 있습니다.
사이트 표시 수량은 서버의 최종 선점·결제 성공을 보장하지 않습니다.
수량 확인은 외곽 옵션과 독립적이며, 표시 문구·수량을 읽을 수 있을 때 사용할 수 있습니다.

수량 판단 재점검에서 숫자 일부와 설명 속 문구를 현재 선택 수로 오인하는 사례를 수정했습니다.
취소표는 같은 화면의 최신 좌석 후보를 먼저 반영한 뒤 수량에 따라 클릭·새로고침·구역 이동을
결정합니다. 후보 분석이 실패하면 이전 화면의 후보로 진행하지 않습니다. 이미 목표 수량을
확인한 완료 처리와 첫 구역 진입은 이 좌석 후보 조건과 별개입니다.
판독 실패는 문구 미검출·중복, 숫자 불명확, 선택 없음 안내 영역 미확인 등 원인을 상태에 표시합니다.
[선택 수량 전체 검토](verification/selection-count-audit/README.md)에 재현·검증 범위를 정리합니다.

제공된 좌석 이미지와 합성 사례를 검사했습니다. 실제 예매창 전환, OS 클릭,
Windows 실행을 확인한 단계는 아닙니다. 서로 다른 클릭 대상이 같은 픽셀로 보이면 외곽만으로 구별할 수 없습니다.
내부에 배경색 표시가 있거나 반복 외곽이 부족한 배치는 지원이 제한됩니다. 검증 기록은
[비원형 확장 검토](verification/nonround-seat-objects/README.md)와
[이전 좌석 객체·수량 검토](verification/seat-object-system/README.md)에 정리합니다.

## 0.5.9 이후 검토 기록 — 좌석 중복 방지와 연석 우선 (당시 미배포)

다음은 좌석 외곽 옵션 추가 이전의 수정·검토 기록입니다.
2·3석 실행에서 같은 좌석의 색상 영역이 변하면 새 ID로 재클릭·집계되는 결함을 재현하고 수정했습니다.
클릭한 색상 성분의 원래 외접 사각형과 클릭점을 기억해 축소·분리된 조각의 재클릭을 막습니다.
실제 윤곽을 추적하는 것은 아니므로 사각형 내부 빈 공간의 별개 후보까지 제외할 수 있습니다.
좌석 후보와 클릭 직전 검사에는 불투명한 2×2 색상 영역을 요구합니다. 1×3 같은 잔여 조각은 제외합니다.
구역·일반 버튼의 인식과 기존 클릭 간격은 유지합니다.

새 **추가 기능 → 연석 우선**은 기본 OFF입니다. 켜면 같은 줄의 2·3석 등 목표 매수 그룹을 우선하고,
없으면 가능한 부분 연석을 잡은 뒤 떨어진 좌석으로 채웁니다. 이미 잡은 자리 옆 후보를 우선하며,
후보가 부족하면 완료를 누르지 않고 계속 탐색합니다. 좌석 번호가 아닌 색상 영역의 크기·간격을 사용합니다.

직전 수정 단계에서 JavaScript 143개·Rust 297개, 총 **440개** 자동 검사와 독립 검토를 통과했습니다.
실제 사이트의 성공을 확인한 것은 아니며, 얇은 외곽선 좌석 누락·같은 색 비좌석 오인·선택 추정의 한계는 남습니다.
그 검토 당시 기존 0.5.9 앱·ZIP은 그대로였고, 해당 수정의 배포 빌드는 하지 않았습니다.
[재현·수정·검증 기록](verification/adjacent-seat-audit/README.md).

이후 상호 리뷰에서 작은 별도 후보가 같은 줄의 연석을 분리하던 그룹화 오류를 수정했습니다.
취소표 탐색 중 과거 후보가 누적되지 않도록 현재 화면과 처리 중인 후보만 보관하며,
선택 확인 중 같은 ID의 모양이 변해도 실제 클릭했던 원래 지점을 유지합니다.
실제 픽셀 모양을 비교하는 시제품은 선택 표시가 중앙으로 옮겨질 때 새로운 재클릭을 허용해 채택하지 않았습니다.
그 검토 단계에서는 사각형 방식의 과도한 제외와 처음부터 여러 색 조각으로 나뉜 좌석의 오인이 미해결이었습니다.
해당 검토 당시 수정은 미배포였으며, [상호 리뷰와 최종 검증 기록](verification/seat-review-cycle/README.md)에 근거와 한계를 남깁니다.

## 0.5.9 배포 기록

0.5.8 이후 검토한 수정사항을 포함한 macOS 실험용 배포입니다. 첫 문자 입력의 macOS 수신 대상 판정,
앱 안의 **키보드 수신 확인**, 취소표 모드별 설정 적용, F8·시작·중지의 비동기 충돌 처리를 개선했습니다.
화면 배율에 따라 좌석 후보의 옆 픽셀을 읽어 클릭을 거부하던 좌표 변환도 수정했습니다.
기존 진입 버튼 순서, 첫 입력에서 기준 색만 저장하는 방식, F9와 선택 추정 정책은 유지합니다.
**0.5.9 빌드 완료:** JavaScript 141개·Rust 270개(총 411개), Swift arm64/x86_64 컴파일·호스트 ABI,
앱 빌드·서명과 검사 전후 소스 96개 파일 동일성 검사를 통과했습니다. 배포 앱은 Apple Silicon·macOS 13 이상용이며,
ZIP 재추출 후 파일·권한·앱 서명도 확인했습니다. [검사 결과](verification/local-checks-0.5.9.json),
[빌드 로그](verification/build-0.5.9.log), [배포 기록](verification/build-artifacts-0.5.9.json).

**실험 순서:** 기존 앱을 완전히 종료하고 0.5.9를 실행합니다. ‘실행 → 키보드 수신 확인’에서
연결한 Chrome의 일반 입력란에 영문자를 입력해 ‘대상 확인’ 수를 확인하세요.
이후 ‘NOL 캡챠 판단’을 켠 F1 실행에서 첫 문자에는 기준 저장만 하고,
직접 캡챠를 완료해 창이 닫힌 뒤 구역·좌석으로 이어지는지 확인합니다.
F4로 중지한 뒤 취소표 방식을 ‘한 구역 · 현재 좌석 계속 탐색’, ‘취소표에서 버튼 사용’을 OFF로 두고
F2를 눌러 빈 화면에서도 재탐색을 계속하는지 확인하세요. F5는 좌석 바로 탐색, F4는 중지입니다.

**남은 한계:** 구역 전환 중 이전 화면과 동일한 완료 화면의 구분, 늦게 뜬 실패창의 좌석 귀속,
같은 색 범례·붙거나 작은 좌석 인식, 선택 추정과 사이트의 실제 선택 불일치는 해결되지 않았습니다.
실제 예매창 동작과 Windows 배포는 별도 검증이 필요합니다.
상세 근거는 [우선순위 검토](verification/priority-audit/README.md),
[취소표 검토](verification/cancellation-audit.md), [공통 동작 검토](verification/multi-agent-audit.md)에 있습니다.

등록한 진입 버튼을 처리한 뒤 캡챠는 사용자가 입력하고, NOL 캡챠 창이 사라지면 구역·좌석 탐색으로 진행합니다.

사용자의 빌드 요청에 따라 macOS 앱 빌드와 서명 검사를 완료했습니다.

**좌석 바로 탐색**을 별도로 선택하거나 F5를 누르면 공통 좌석 색상·범위에서 바로 시작하며
예매 진입·예약·날짜·회차·구역 선택 설정은 이 모드에 적용하지 않습니다.
좌석 후보가 없을 때 같은 구역의 화면을 주기적으로 다시 탐색합니다.
**일반 예매 → 캡챠 Enter 후 구역부터 자동 진행**만 켜면 지정한 **날짜 버튼 → 회차 버튼 →
다음 / 예매 버튼**을 기존 클릭 간격으로 누른 뒤 캡챠 Enter를 기다립니다.
미지정 단계는 직접 진행하고, 캡챠 제출 Enter로 구역 탐색을 시작합니다. 오입력으로 다시 Enter를 누르면 이전 대기 클릭과
후보·선택 추정을 비우고 구역부터 다시 찾습니다. 구역 자동 선택을 끄면 좌석 탐색으로 이어집니다.
재입력 Enter로 날짜·회차·다음 버튼이나 판매 시작 예매 버튼을 다시 누르지는 않습니다.
Enter는 브라우저에 그대로 전달하며, 정답 여부를 판정하는 신호로 취급하지 않습니다.
**NOL 캡챠 판단**은 같은 진입 순서를 유지합니다. 0.5.8에서는 첫 영문자·숫자 입력에
창 왼쪽 아래 기준 색을 저장한 뒤 색 변화로 진행합니다. 다른 입력란에서 먼저 타이핑하거나
해당 위치의 배경이 별도로 달라지면 오인하거나 대기가 유지될 수 있습니다.
이 옵션을 켜면 Enter로 먼저 진행하지 않으며 취소표·좌석 바로 탐색에는 영향을 주지 않습니다.
일반 예매의 Enter/NOL 진행, 좌석 바로 탐색, 한 구역 취소표에서는 클릭 전달을 **선택 추정**으로 셉니다.
선택 후 색상이나 사이트 매수 표시를 기다리지 않습니다. **안내창 자동 대응**을 켜면
좌석 클릭 뒤 중앙 화면 변화 **또는** 주변 어두워짐을 감지해 직전 클릭을 실패로 추정합니다.
그 클릭만 차감하고 Esc를 한 번 보낸 뒤 화면 복귀를 감지하면 부족분 탐색을 재개합니다.
감지는 좌석을 고르는 동안만 수행하며 **선택 완료 버튼을 누르기 직전**에 끝납니다.
문구·HTML을 읽지 않는 화면 변화 추정이므로 실제 오류 종류나 실패 좌석을 확정하지 않습니다.
화면이 바뀌면 즉시 확인하며, 정적 화면은 설정한 간격으로 재확인합니다.
일시적으로 다른 창이 앞에 있거나 캡처가 끊기면 클릭을 보류하고 대상 복귀를 확인합니다.
같은 창·위치·배율과 유효한 캡처가 확인되면 자동 재개하며, 명시적 일시정지·중지는 자동 재개를 취소합니다.
앱의 시작·재개·단계 확인 버튼은 연결한 예매창을 활성화한 뒤 진행합니다.
기존 원본 경로에서 이미 좌석 화면인데 구역 탐색 중이거나 그 상태에서 일시정지했다면,
예매창에서 F6을 눌러 현재 좌석 화면을 확인하고 좌석 탐색으로 넘어갈 수 있습니다.
Enter 진행과 한 구역 취소표의 구역 클릭 뒤에는 새 프레임에서 좌석 탐색을 이어갑니다.
모든 모드는 **선택 완료 버튼의 입력 전달 뒤 실행을 종료**하며 최종 성공 확인이나 F6을 요구하지 않습니다.
0.5.3의 Dock 가림 판정·Chrome 보조창 처리와 F8 오류 표시 수정도 유지합니다.
예약 시각에 지정한 예매 버튼을 한 번 클릭하는 0.5.1의 동작은 유지합니다.
UI·관찰기 테스트와 Swift 네이티브 모듈 검사 결과는
[`verification/local-checks.json`](verification/local-checks.json)과
[`native/VERIFICATION.md`](crates/macro-platform/native/VERIFICATION.md)에 구분해 기록합니다.

## macOS 업데이트

1. F4로 중지한 뒤 기존 앱을 완전히 종료하세요.
2. 새 패키지의 `Integrated Macro.app`으로 이전 앱을 교체한 뒤 실행하고 화면의 **v0.5.11**을 확인하세요. 두 버전을 동시에 실행하지 마세요.
3. 예매창을 다시 연결하세요. 창 크기·배율이 바뀌었다면 좌표를 다시 지정하세요.

앱 식별자 `dev.integrated-macro.desktop`과 설정 저장 경로는 유지합니다.
설정·권한의 자동 승계를 보장하지 않으므로 실행 후 저장된 옵션을 확인하세요.
이전 앱은 자동 교체하지 않습니다. 새 앱에서 입력·화면 읽기가 실패하면
**시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용 / 화면 및 시스템 오디오 기록**에서
새 앱의 권한을 확인하고 앱을 다시 실행하세요. OS 버전에 따라 화면 기록 항목의 이름은 다를 수 있습니다.
업데이트 후 권한 유지는 보장하지 않습니다.
앱은 기존과 같은 로컬 임시 서명(ad-hoc)을 사용하며 Apple 공증을 받은 앱은 아닙니다.

| 브라우저 관찰기 | 연결 방식에 독립적인 날짜·회차·진입 단계 분류 모듈과 테스트 |

**HTML·브라우저 이벤트를 읽는 연결은 아직 구현하지 않았습니다.** 이번 안내창 대응은
확장을 추가하지 않고 기존 OS 화면 캡처를 사용합니다. 날짜·회차 버튼을 화면에서 자동으로 찾아내는 기능과
캡챠 정답·실제 오류 종류·최종 성공·사이트의 자동 갱신 판정은 미구현입니다.
Enter를 사용자의 제출 신호로 받아 진행하고, 취소표는 사이트 갱신 확인 없이 화면을 계속 읽습니다.
지금 보이는 예매 버튼의 좌표를 지정해 예약 시각에 클릭하는 경로는 구현되어 있습니다.

구역의 무대 기준도 실제로 보이는 화면에서 지정합니다. 사전 배치도와 열린
화면의 자동 대응은 아직 구현하지 않았습니다. 특정 공연의 숨겨진 예매 화면을
미리 방문하거나 그 좌표를 모두 등록해야 시작할 수 있는 구조는 아닙니다.

## 빌드 준비와 명령

현재 안정 Rust/Cargo와 Node.js가 필요합니다. macOS는 Xcode Command Line Tools,
Windows는 C++ 빌드 도구와 WebView2 개발 환경이 필요합니다.
[Tauri 공식 준비 안내](https://v2.tauri.app/start/prerequisites/)를 참고하세요.
이 구현의 macOS 배포 대상은 13 이상입니다.

현재 Mac에는 Node.js와 Xcode가 설치되어 있습니다. 다운로드 가능한 터미널에서
아래 명령으로 Rust 설치부터 의존성·테스트·앱 빌드까지 진행할 수 있습니다.

```sh
bash scripts/bootstrap-macos.sh
```

공식 Rust 설치 도구의 SHA-256을 확인한 뒤 `.build-tools/` 안에 도구를 설치합니다.
설치 방법은 [Rust 공식 문서](https://rust-lang.github.io/rustup/installation/other.html)를
따릅니다. 사용자 셸 설정은 수정하지 않으며, 결과 로그는
`verification/build-macos-latest.log`에 남깁니다. 네트워크 접속이나 테스트가
실패하면 빌드를 완료로 표시하지 않고 중지합니다.

이 폴더에서 실행합니다.

```sh
npm install
npm test
cargo test --workspace
npm run dev
npm run build
```

- `npm test`: UI 설정 직렬화와 브라우저 단계 관찰 테스트. 외부 사이트 접속 없음.
- `cargo test --workspace`: 공통 엔진·플랫폼·데스크톱 코드 테스트.
- `npm run dev`: Tauri 앱 실행. 실제 입력은 대상 연결 후 사용자가 시작해야 발생합니다.
- `npm run build`: 현재 OS용 앱 빌드. 결과는 `target/release/bundle/`.
- `node scripts/check.mjs --native`: 가능한 검사와 소스 해시를 기록합니다.
  필수 도구가 없으면 종료 코드 2, 실패하면 1입니다. 누락된 검사를 통과로 표시하지 않습니다.
- `node scripts/check.mjs --native --build`: 테스트와 네이티브 검사를 통과하고 소스가
  그대로일 때 Mac 앱을 빌드하고 번들 서명을 검사합니다. 실패·누락 시 빌드를 시작하지 않습니다.
  의존성이 이미 준비된 환경에서 오프라인으로 실행합니다. Mac 앱은 로컬 서명이며 Apple 공증은 아닙니다.
- Mac: `bash scripts/build-macos.sh`
- Windows PowerShell: `.\scripts\build-windows.ps1`

각 OS에서 직접 빌드·실행 검증해야 합니다. `.github/workflows/desktop.yml`은
이 폴더를 저장소 루트로 사용할 때의 양쪽 OS 검사 설정이며, 여기서는 실행하지
않았습니다. `Cargo.lock`·`package-lock.json`으로 설치된 의존성을 고정합니다.

## 사용 흐름과 단축키

1. 설정을 저장하고 현재 예매창을 앞에 둔 뒤 **F7**로 연결합니다.
2. 앱에서 항목의 **F8로 지정**을 누르면 설정 화면이 최소화됩니다.
   예매창으로 전환해 대상 위에 마우스를 두고 **F8**을 누르세요.
   바로 읽고 저장하며 성공하면 소리와 좌표를 표시합니다. 타이머는 없습니다.
   좌표를 읽을 때는 연결한 창이 마우스 아래에 보이면 됩니다. 실패하면 해당 항목과
   상단 표시창에 이유가 남으며 F8로 재시도할 수 있습니다. 다른 예매 팝업이면
   그 창을 전면에 두고 F7로 다시 연결한 뒤 해당 항목의 **F8로 지정**을 다시 누르세요.
3. 좌석 화면에서 공통 좌석 색상과 **좌석 영역** 두 모서리를 지정하고 앱에서
   **좌석 바로 탐색**을 선택해 **좌석 바로 탐색 시작**을 사용하거나 예매창에서 **F5**를 누릅니다.
   이 모드는 구역 진입 확인 없이 바로 탐색합니다.
   예약에는 **일반 예매** 모드에서 **판매 시작 예매 버튼**을 지정하세요.
   **캡챠 Enter 후 구역부터 자동 진행**을 켜면 **기존 좌표로 시작**에 지정한
   **날짜 버튼 → 회차 버튼 → 다음 / 예매 버튼**을 먼저 누릅니다. 미지정 단계는 직접 진행하세요.
   캡챠 제출 Enter로 탐색을 이어갑니다. 틀렸다면 다시 입력하고 Enter를 누르세요.
   같은 실행에서 구역·좌석만 다시 찾으며 날짜·회차·다음 버튼은 반복하지 않습니다.
   이 옵션을 끈 기존 예매 진입 경로는 실제 좌석 화면에서 F6으로 확인합니다.
4. **F1** 일반 예매 / **F2** 취소표 탐색 / **F3** 일시정지·재개 /
   **F4** 중지 / **F5** 좌석 바로 탐색을 사용합니다. 실제 실행 전에 연결한 예매창을 활성화하세요.
   F1·F2·F5는 앱의 실행 방식 선택과 관계없이 각각 일반 예매·취소표 탐색·좌석 바로 탐색이며,
   현재 화면 옵션을 저장해 적용합니다. F2도 저장 전 새로고침 OFF 선택을 적용합니다.
   F5는 브라우저 새로고침 용도가 아닙니다.
   설정 오류·저장 실패·초기화 중에는 시작하지 않습니다. 다른 요청 처리 중에는 끝난 뒤 다시 누르세요.
   앱의 각 **시작**·재개 버튼은 연결한 창으로 전환한 뒤
   실행합니다. 예약 시작에도 적용됩니다. 전환 실패 시 입력하지 않고 이유를 표시합니다.
5. 처음 보는 구역·좌석 화면에서는 일시정지하고 해당 화면의 탐색 범위·색상·
   무대 기준·선택 완료 위치를 지정할 수 있습니다. 저장 후 같은 실행을 재개합니다.
6. 취소표에서 버튼을 누르려면 **한 구역 · 취소표 새로고침 버튼** 방식을 선택하고
   **취소표에서 버튼 사용**을 켠 뒤 **취소표 새로고침 버튼**을 F8로 지정하세요.
   사용을 끄거나 좌표가 없으면 버튼을 누르지 않고 계속 탐색합니다. 브라우저 새로고침 키는 보내지 않습니다.
   일반 예매와 좌석 바로 탐색에는 이 버튼 설정이 적용되지 않습니다.
   버튼 없이 현재 좌석 화면을 계속 읽으려면 **한 구역 · 현재 좌석 계속 탐색**을 선택하세요.
   한 구역 취소표는 일반 예매의 예약·진입·구역 자동 선택을 건너뛰고 현재 좌석 화면에서 시작합니다.
   한 구역 취소표는 공통 좌석 색상·좌석 영역·**좌석 선택 완료 버튼**을 사용합니다.
   공통 완료 버튼이 없으면 목표 매수 뒤 자동 완료 클릭을 할 수 없으므로 직접 진행하고 중지하세요.
   아래 구역별 색상·영역·완료 버튼은 원본 두 구역·위/아래 이동의 활성 구역에만 적용됩니다.
7. 취소표의 실패 후보는 재탐색 간격이 지나면 다시 허용합니다. 사이트 자동 갱신을
   판정하거나 F6으로 확인할 필요가 없습니다. 정상 안내창 감지·복귀도 자동으로 이어갑니다.
   원본 두 구역·위/아래 키 경로의 구역 전환·선택 확인에는 기존 F6 보완을 유지합니다.

Mac 기능 키 설정에 따라 Fn이 필요할 수 있습니다. 단축키 등록 실패는 준비
상태에 표시됩니다. 화면 기록과 입력 권한은 별개입니다. 창 위치·크기·배율·
대상 변경이나 다른 창의 가림은 해당 입력을 차단합니다.
예약 시작 후에는 연결한 예매창을 앞에 두세요. 예약 시각에 다른 앱을 강제로
앞에서 밀어내는 기능은 없으며 실제 클릭 시 전면·가림 검사를 유지합니다.
`accessibility_permission`이면 **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**
에서 **Integrated Macro**를 허용하고 앱을 다시 실행하세요. `target_focus_unavailable`은
예매창을 클릭한 뒤 F7로 다시 연결하고, `target_hit_test_unavailable`은 Dock·메뉴를
닫고 예매창의 대상 위에서 F8로 재시도하세요. 진단 스크립트의 `screenPermission`은
그 스크립트를 실행한 프로세스의 값이며 매크로 앱의 권한을 뜻하지 않습니다.
F8 지정 안내·결과·오류는 상시 상태창 기능을 꺼 두어도 잠시 표시합니다.
`runtime-events.jsonl`은 설정과 같은 앱 데이터 폴더에 저장합니다. 화면 이미지는 기록하지 않습니다.
Mac 경로는 `~/Library/Application Support/dev.integrated-macro.desktop/`입니다.

추가 기능이 꺼진 원본 방식에서는 클릭 시도를 기록하고 다음 좌석을 클릭합니다.
**입력 전달을 좌석 확보로 표시하지 않습니다.** 목표 수에 도달하면 지정한 완료 버튼을 시도하고,
입력 전달 시 실행을 끝냅니다. 버튼 미지정 시 직접 진행 후 중지하거나 버튼을 지정해야 합니다.
현재 수동 **직전 클릭 선점 실패 확인**은 마지막으로 전달한 좌석 클릭을 실패 처리합니다.
복구 옵션이 켜져 있으면 Esc를 한 번 보내고, 닫힘을 확인한 뒤 부족분 탐색을 이어갑니다.
Enter 진행·좌석 바로 탐색·한 구역 취소표의 **안내창 자동 대응**은 동일한 복구 옵션을 사용합니다. 중앙 변화나 주변 어두워짐을
안내창 후보로 판단하며 같은 안내창이 유지되는 동안 반복 차감하거나 Esc를 반복하지 않습니다.
원래 화면에 가까워지면 닫힘으로 판단합니다. 완료 버튼 뒤 처음 나타난 오류는 이 감지 범위에 없습니다.
여러 클릭 뒤 늦게 도착한 일반 오류창만으로 실패 좌석을 정확히 구별할 수 없으며,
사이트가 다른 선택도 해제한 경우에는 추정 매수가 실제와 달라질 수 있습니다.
원본 F2의 구역 지연은 유지하지만 향상된 복구·갱신 모드에서는 새 화면 확인을 기다립니다.
연석 우선은 이미지로 추정하며 좌석 번호 기반 연속성 보장은 하지 않습니다. 결제 단계로 진행하지 않습니다.

## 설정·시간·성능의 한계

- 전체 과정의 수동 개입·대기와 미구현 사항은
  [남은 대기·수동 개입 점검](docs/implementation-status.md#남은-대기수동-개입-점검)을 참고하세요.
- 안내창 감지는 작은 픽셀 표본 비교이며 클릭마다 별도 성공 확인 시간을 추가하지 않습니다.
  연속 탐색 경로는 실제 입력 하나마다 새 화면과 제어 요청을 확인합니다. 기존 클릭 간격·캡처·입력 비용은 남습니다.
  중앙의 정상적인 큰 변화도 오감지할 수 있고, 작은 안내창이나 캡처에 포함되지 않는 별도 창은 놓칠 수 있습니다.
  화면이 원래 상태로 돌아오지 않으면 복귀 대기가 유지됩니다. 실제 사이트의 정확도·지연은 미검증입니다.
- **빈 좌석 재탐색·새로고침 간격**은 기본 1,000ms이며 일반 예매에도 적용합니다.
  빈 좌석 화면의 재분석은 사이트 새로고침이나 선택 성공을 의미하지 않습니다.
  후보가 없어도 계속 탐색하며, 이미 클릭한 좌석의 결과가 미확정이면 중복 클릭하지 않습니다.
  취소표에서만 명시적으로 설정한 내부 버튼을 사용하고, 입력 후 이전 이미지를 새 좌석 클릭에 쓰지 않습니다.
  취소표 실패 후보의 재허용은 재시도 정책이며 실제 갱신 성공을 뜻하지 않습니다.
  일부 좌석을 골랐다면 선택 유지를 위해 내부 새로고침과 구역 이동을 보류하고 부족분을 탐색합니다.
- Enter는 일반 예매 실행 중 연결한 창에서 누른 새 입력을 사용합니다. 중지·일시정지·채집 중,
  다른 앱, 오래된 이벤트, 키를 누르고 있어 발생한 반복 입력은 시작 신호로 사용하지 않습니다.
  Enter 이전 이미지의 재사용을 제한하지만 실제 CAPTCHA 정답이나 화면 의미를 판별하지는 않습니다.
- 연속 탐색의 자동 복귀는 전면 창·가림·일시적 캡처 오류에만 적용합니다.
  권한 상실, 대상 창 종료·크기·배율 변경, 입력 전달 여부가 불명확한 오류는 직접 확인이 필요합니다.
  동일 창 안의 다른 탭·캡챠·안내창을 모두 식별하는 기능은 없으므로 실제 좌석 화면에서 사용해야 합니다.
- 최근 탐색 진단에는 실제 적용한 색상·범위와 색상 후보 수를 표시합니다.
  아직 좌석 분석을 실행하지 않은 경우와 분석했지만 색상 일치 픽셀이 없는 경우,
  크기 조건에서 후보가 제외된 경우를 구분합니다. 이 숫자는 색상 후보이며 좌석 확보 수가 아닙니다.
- 설정은 OS별 앱 데이터 폴더의 `settings.json`에 저장합니다. 실행 중 사용한 단조
  시계 마감값은 새 실행에서 다시 계산하며 저장값을 재사용하지 않습니다.
- 원본 `Save1.ini`–`Save6.ini`는 한 설정을 나눠 저장한 묶음입니다.
  이번 버전에는 해당 파일의 자동 가져오기가 없습니다. 기존 파일은 보존했습니다.
- HTTP Date는 초 단위이고 응답한 CDN 등의 시각일 수 있습니다. 표시한 오차는
  시각 헤더·통신 측정의 추정 범위이며 실제 판매 서버 개방 시점을 보장하지 않습니다.
- 색상만으로 범례와 좌석의 의미를 완전히 구분할 수 없습니다. 현재 화면의 탐색
  범위에서 범례를 제외해야 합니다. 무대 중앙 판정은 지정한 기준점의 수직선에
  가까운 후보를 먼저 고르는 기하 방식이며 운영사 구역 의미와의 일치 검증이 필요합니다.
- 좌석 색 변화는 최종 선점의 증거가 아닙니다. 선택 표시와 최종 성공을 구분합니다.
- 캡처 이미지는 UI로 전달하지 않고 엔진에서 빌려 읽습니다. 권한 검사는 각 프레임마다
  반복하지 않습니다. 아직 실제 예매 환경의 지연·오클릭 비율을 측정하지 않았습니다.
- 작은 보조창 때문에 활성 창 확인이 추가로 필요할 때 화면 관찰은 최대 75ms 동안
  확인 결과를 재사용합니다. 창 목록·위치 변경은 즉시 재확인하며, 실제 입력과 F8 위치
  확인에는 저장된 판정 결과를 사용하지 않습니다.

상세 검증 항목은 [개발·검증 기록](docs/implementation-status.md)을 확인하세요.
