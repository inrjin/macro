# F8 capture regression — 0.5.2

## Observed failure

The user's 00:30:35 event sequence reached `capture_frame` for `legacy.session`.
The app log then returned `[target_not_foreground]` immediately (same millisecond),
followed by an error state. Earlier attempts also returned `[target_window_changed]`.
There was no evidence of a hung capture call in this sequence. The exact active
application at that instant was not recorded.

The F8 read path shared the keyboard-focus gate used for automated input.
The UI then treated `captureArmed: true` as an unconditional waiting state,
erasing the visible capture failure.

## Fix and verification

- F8 samples only the bound window visibly underneath the pointer; it checks
  identity, geometry and occlusion before and after reading. Input retains its
  foreground checks. The production validator passes 18 synthetic window cases.
- Capture errors remain in `captureState` and `captureError`, including bootstrap
  after a missed event. Retry and successful capture clear the old failure.
- The shipped `app.js` and `overlay.js` run unchanged against their actual HTML
  in an isolated VM DOM. The regression replays arm, read, error, retry and
  received coordinate `(240, 360)`. It checks the row, activity, guide, status bar,
  overlay, saved-value display and old error removal. JavaScript tests: 46 passed.
- Rust workspace tests: 77 passed. Optimized Swift arm64/x86_64 and host C ABI,
  capture lifecycle and buffer checks passed. The test process permission bits
  were zero; it did not capture a real screen or send input.

The final build, bundle-signature check and source SHA-256 values are recorded
in `local-checks.json`. They must all pass before packaging this source.

## Explicit gaps

An isolated Chrome UI run was attempted but local HTTP listening was blocked
with `EPERM` by this environment before Chrome started. The VM test does not
validate browser rendering, Tauri event transport, real F8 delivery, actual
screen capture, or mouse input. No existing Chrome profile or logged-in booking
session was accessed, and no denied permission was bypassed. Windows source
passed a standalone Rust metadata typecheck; a complete Windows app build and
actual Windows input remain unverified.

This is a regression-checked development build, not proof of end-to-end Mac
operation or readiness for a live ticket sale.
