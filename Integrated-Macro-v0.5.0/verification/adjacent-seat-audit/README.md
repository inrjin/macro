# 좌석 중복·잔여 색상 조각·연석 우선 검사

2026-10-21 · v0.5.9 배포 뒤 소스 수정, **미배포**

## 보고와 관측 근거

사용자는 2·3석 설정에서 한 좌석을 잡은 뒤 그 좌석을 다시 인식하거나 비활성 이웃을 클릭하고 완료해 실제 1석만 남는다고 보고했다.
기존 ‘목표 좌석’은 수량만 지정했다. 사용자가 이번에 확정한 우선순위는 **같은 줄 연석 → 부족하면 분리 좌석**이다.

실행 기록의 run 3/5/6은 물리 픽셀 `(106,921) → (122,920) → (142,1101)`을 클릭한 뒤 완료 입력을 전달했다.
100ms와 500ms 간격에서 같은 순서였다. 두 번째 후보 ID는 `pixel:122:919`이며,
RGB `(185,224,180)`, 허용 오차 12, 화면 배율 2였다. 원래 캡처 이미지는 없으므로
해당 후보가 실제로 어떤 그림이었는지, 서버가 각 클릭을 수락했는지는 로그만으로 확정할 수 없다.
[관측 요약](run-summary.json), [문자·주소 없는 관련 이벤트](reported-run-events.json).

## 재현한 결함과 수정

1. 같은 물리 좌석의 색상 영역이 9×9 → 7×7 → 5×5로 줄면 ID가 바뀌었다.
   실제 추출기와 엔진은 동일 클릭점을 서로 다른 3석으로 계산했다.
   이제 실제 전달한 후보의 원래 영역과 클릭점을 기억해 새 ID·분리 조각도 중복에서 제외한다.
   미전달 취소, 실패 후보 재시도, 유지 좌석, 새 실행, 구역 구분을 별도로 검사했다.
2. 1×3 색상 조각으로 로그의 두 번째 후보 ID와 클릭점을 재현했으며, 기존 단일 픽셀 검사도 통과했다.
   이제 좌석 추출과 클릭 직전 확인 모두 불투명한 2×2 색상 영역을 요구한다.
   클릭점도 그 영역의 구성 픽셀에서 고르고 원래 성분 전체 경계는 보존한다. 구역 인식은 유지한다.
3. ‘연석 우선’을 독립 ON/OFF 옵션으로 추가했다. 기본 OFF이며 ON이면 목표 매수를 채우는 같은 줄 그룹,
   가능한 부분 그룹, 분리 좌석 순으로 선택한다. 이미 클릭한 좌석 옆 후보를 우선 보충한다.
   행은 성분 높이에 비례한 중심 차이, 이웃은 비슷한 성분 폭과 짧은 틈으로 추정한다.
   빈 중간 좌석을 건너뛴 점 간 거리를 새 좌석 간격으로 학습하지 않는다. 추가 서버 대기나 간격 클릭은 없다.

## 남은 한계

실제 예매창의 원프레임과 OS 클릭을 재현하지 않았으므로 사용자가 보고한 모든 현장 원인이 해결됐다고 단정하지 않는다.
2×2 면적이 없는 얇은 정상 좌석도 제외될 수 있다. 반대로 비활성 좌석·범례가 같은 색의 충분한 면적을 가지면 통과할 수 있다.
붙은 같은 색 좌석은 하나의 성분으로 합쳐질 수 있고, 잘린 ROI의 큰 물체도 후보가 될 수 있다.
그룹 판정은 좌석 번호 기반 연속성 보장이 아니다. 사이트가 오류창 없이 입력을 무시하거나 이전 선택을 지우면
기존 ‘선택 추정’과 실제 확보 수는 여전히 다를 수 있다.

앱 배포 빌드·실제 Windows 입력·장시간 실행·실측 반응 속도는 이번 검증에 포함하지 않았다.
