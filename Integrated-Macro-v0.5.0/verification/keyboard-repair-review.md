# 키보드 입력 필터 수정 검토

## 확인된 원인

사용자가 보낸 실제 입력 로그에서 동일한 시각의 문자 입력 9개가 두 감시 API 모두에 도착했다. Chrome PID는 `19961`, 검사 프로세스 PID는 `73574`였다.

| 수신 경로 | 앞에 있는 앱 PID | 이벤트 수신 PID | 기존 필터 결과 |
| --- | --- | --- | --- |
| CGSession tap | 19961 | 19961 | 허용 |
| NSEvent global monitor | 19961 | 73574 | `recipient_mismatch` |

프로덕션은 NSEvent 경로를 사용한다. 이 환경에서 관측자 PID로 표시된 수신자를 실제 목적 앱으로 해석한 조건이 정상 입력을 거절했다. 검사 프로세스의 권한은 모두 허용이었고 보안 키 입력은 꺼져 있었다. 배포 앱 자체의 권한 상태를 증명하는 결과는 아니다.

## 소스 변경

- NSEvent 감시 콜백에서 수신 PID가 관측자 자신인 경우에만 수신자 미상으로 처리한다. 문자와 Enter 경로 모두 적용했다.
- 원래 PID는 진단에 남기며, 자체 생성 입력·자체 전면 앱·무관한 수신자·오래된 이벤트는 계속 제외한다. 연결 창 검증도 유지했다.
- 배치의 첫 입력이 만료됐을 때 뒤의 유효한 입력까지 버리지 않도록 최대 16개를 순서대로 보관한다.
- 첫 문자는 기준색만 저장한다. 이후 화면 변화가 있어야 캡챠 판단이 진행된다.
- 앱에 약 20초 동안 실행하는 **키보드 수신 확인**을 추가했다. 앱 자신의 권한과 수신 단계별 수치를 보여주며 예매 클릭·화면 채집·프로필 저장은 실행하지 않는다. F4로 중지할 수 있다.

## 검증

- JavaScript 132개, Rust 222개 통과.
- Mac arm64·x86_64 Swift 컴파일 및 호스트 ABI 검사 통과.
- 사용자 로그의 9개 입력 메타데이터를 문자·Enter 경로 각각의 콜백→큐→FFI에 재생해 한 번씩 전달되는지 확인했다. 거절 조건과 500ms 만료 검사도 통과했다.
- 3개 보조 에이전트가 구현과 교차 검토를 분담했다. 마감 직전 입력 누락, 이전 단축키 응답의 검사 중단, 과거 F8 결과의 표시 충돌을 검토 과정에서 수정했다.
- 검사 종료 시 소스 지문이 시작 시점과 동일하다. 기존 0.5.8 배포 앱·ZIP과 루트 AGENTS.md는 그대로다.

## 아직 확인하지 않은 범위

실제 배포 앱의 물리 입력 수신→기준색 저장→캡챠 종료 진행은 아직 실행하지 않았다. 메타데이터 재생은 실제 앱 실기 검사를 대신하지 않는다. Windows 빌드·실행과 좌석 선점 성공도 검증하지 않았다. 기존 좌석 영역 누락의 발생 원인은 별도 확인이 필요하다.

배포 빌드는 실행하지 않았다. 사용자의 빌드 전 상담 요청에 따라, 이 변경과 검사 결과를 검토한 뒤 새 앱을 패키징한다. 터미널 권한 변경이나 세션 재시작은 수행하지 않았다.
