# Independent non-round object integration review

**Current integration checkpoint:** the earlier 8-test/source-hash checkpoint predates the adversarial open-white-stripe failure; the later 10-test checkpoint predates the temporal interpretation failure. Both are historical. The implementation now holds all members of a locally ambiguous whole-object interpretation and revalidates changed observation context. The latest independent integration log has **11 passed / 0 failed**. Full-workspace validation is owned by the parent.

Scope: actual image extractor, original candidate pre-click proof, Engine identity/adjacency/count policy, and a separate analytic site hit/toggle oracle. This review did not run the app, an operating-system input hook, a browser, or the selection-count text reader. Production edits belong to the parent and implementation agent.

## Findings and responses

- **Bounding-box identity:** `seat_selection::same_seat` previously treated another click point inside a bbox as the same seat. Two independent 37×7 rectangles rotated 45° with centers 14 pixels apart have disjoint occupied pixels but boxes containing the other's point. The new full-silhouette test preserves both. `slanted_same_row_pair...` additionally requires the pair to outrank an earlier isolated object only with adjacency enabled. Empty bbox corners are not automatically owned pixels.
- **Actual pre-click proof:** learning a non-round shape is insufficient if the caller reconstructs a circle. Recognition and `seat_object_candidate_supported` now share the process-local shape. The integration runner deliberately retains the original queued proposal while checking the latest image. A stale shape with only the old 2×2 color patch remaining fails. JSON roundtrip omits the proof and cannot authorize object mode; ordinary color mode still uses its separate contract.
- **Changed global interpretation:** the adversarial reviewer then reproduced an unchanged local shape gaining a competing neighboring fragment: full current extraction rejected it while old local proof still allowed it. Shared `SeatObjectContext` binds ROI RGBA including alpha, image geometry, complete vision configuration, registered color, and tolerance. Changed context triggers one full re-extraction of that same acquired frame; the old candidate must still have a permitted equal bounds/shape interpretation, and its original click point must independently pass local validation. IDs are not compared, preserving runtime `zoneN:` prefixes. JSON omits this context too. No atomicity between this frame and the later OS input is claimed.
- **Repeated selected marks:** the adversarial reviewer reproduced white-hole selected styles becoming their own learned family. Rejecting hole-bearing references, without filling them, prevents that learned denominator from erasing the ambiguity. This is a bounded support restriction, not recognition of every hollow/lettered seat.
- **Repeated composite pairs:** the adversarial reviewer reproduced six narrow-bridge pairs becoming six large objects rather than twelve small objects. The correction rejects a composite reference only when at least two independently repeated, disjoint smaller shapes explain at least 80% of it with limited blocked surroundings. Wide solid merges remain a negative case. A real single dumbbell-shaped hit target can have the same pixels as two bridged targets; pixels alone do not resolve that case.
- **Open white stripes:** the adversarial corpus later reproduced six marked objects becoming twelve learned fragments plus the two normal candidates. A global rule excluding available-colored references was rejected because it removes all-available-map support. `fragment_competition` now keeps a sufficiently visible, larger repeated whole interpretation and holds proposals belonging to that local ambiguous footprint. The independent source review also found that marking only the triggering pair would leave a third middle fragment clickable. The implementation marks every proposal at least 90% contained by that competing whole. The 23×15, two-stripe regression passes after this correction. This specific three-piece issue was corrected before its first test execution, so its log is a post-fix regression, not a preserved failing baseline.
- **Resource bounds:** the initial component pass stored all coordinates of oversized connected areas, even though they could not become reference templates. The correction caps retained coordinates to the reference bounds and keeps separate total/color counts for search seeds. Outside-boundary mismatch now exits once its existing rejection limit is exceeded. Template dimensions, family counts, and search positions are bounded; these are not a measured whole-app latency guarantee.
- **Exact foreground upper bound:** the lazy prefix table uses the same allowed-pixel, alpha, background, and contrast conditions as `boundary_observation`. Every template-inside pixel lies in its integer bounding rectangle, so the rectangle foreground count is an upper bound on inside visibility. Rejecting only when that bound is below 90% cannot reject a fit accepted by the existing at-least-90% test. Prefix totals are bounded by checked area; lookup adds in `u64` before subtraction. Failure to build/query the optional table falls back to the original scorer. The independent connected 3×3-grid regression exercises more than 128 search positions, a nonzero ROI origin, and padded stride. Exclusion and opacity semantics are shared, not bypassed. Search-position limits and measured synthetic timings remain distinct from any whole-app latency guarantee.
- **Caller contracts:** runtime still applies object extraction only to seat mode with the optional feature enabled, keeps pending original candidates, prefixes legacy-zone IDs, and validates the latest frame before delivery. Engine marks preserve the original delivered shape; failure/retry and refresh clear only eligible failed marks. Count ON requires observed totals; count OFF remains optimistic delivery estimation.

## Independent tests

`crates/macro-core/tests/seat_object_nonround_integration.rs`: **11 passed** in `after-context-integration.log`. `integration-final.log` preserves the ten-test pre-context checkpoint; `after-shape-review.log` preserves the earlier eight-test checkpoint.

1. Nine independent analytic shape families with count ON/OFF reach two actual distinct objects and then completion.
2. Ordinary color mode remains independently usable with either count policy.
3. Internal dark color splits do not become multiple site objects.
4. The disjoint rotated pair survives bbox containment.
5. Adjacency ON prioritizes that pair; OFF preserves the earlier isolated choice.
6. A stale object with the old color patch is rejected.
7. Serialization cannot recreate learned shape evidence.
8. A successful object and failed neighbor survive a one-pixel repaint/new IDs and Pause/Resume; Refresh releases only the failed neighbor, and an undelivered retry's old ACK is inert. Both count policies are covered.
9. Nine shape families containing ten available objects and no gray reference still acquire three distinct objects and complete with count ON/OFF. This is progress coverage, not an all-unknown safety pass.
10. A repeated selected-style object with two open white stripes leaves no middle fragment clickable; the two separate normal candidates alone reach the count-OFF engine.
11. `zone1:` candidate IDs, unrelated pixels outside the observation ROI, and an unrelated one-pixel change inside the ROI do not cancel a valid candidate or replace its original queued point.

The first run exposed two **test assumptions**, not production defects: internal marks can alter click-point y ordering while still selecting both correct objects, and the original 31×9 fixture's point lay just outside the overlapping bbox. The assertions were corrected to independent object membership and a verified 37×7 containment fixture. Those logs remain preserved.

## Limits

Successful finite fixtures are not proof of actual website seat identity, server acceptance, semantic row numbers, or all possible shapes. Repetition and visible-boundary evidence are required. A count signal can hold on an unexplained decrease, unreadable state, or missing increment; that does not guarantee progress or recover which seat changed. Raw identical pixels may encode different hit targets. Candidate timing/coordinate-platform behavior, stale native-frame fencing, real NOL text reading, and macOS/Windows execution are outside this integration harness.
