# Independent non-round object review

Status: final independent review checkpoint. The scoped corpus has **20 passed / 0 failed / 2 manual benchmarks ignored**; both benchmarks were then explicitly executed and passed. The six reviewed source files were unchanged before/after these checks. Full-workspace verification belongs to the parent. No distribution build or live-site approval is implied.

## Oracle and scope

`crates/macro-core/tests/support/seat_object_shapes.rs` constructs shapes with independent analytic containment and optional 4×4 supersampling. Pixel hit ownership is stored independently of component IDs, learned templates, candidate bounding boxes, and detector output. `seat_object_nonround_review.rs` calls the actual object extractor and the actual pre-click validator. A supported positive must produce exactly one valid click per independently owned object; returning no candidates fails these positives. Explicit ambiguity rejections are recorded separately.

This is synthetic RGBA testing, not native capture, Worker scheduling, physical input, OCR, server seat availability, or successful ticket acquisition. Test timings with concurrent debug tests are not application latency. The ignored optimized benchmark is a separate 1280×800 static scene with 200/1000 objects, three available seats, and one narrow bridge.

## Reproduced findings

1. **Exact learned mask misses ordinary raster variation.** First corpus run (`probe1.log`) missed 14 of 16 AA/subpixel cases and all three ±1px size variants; exact family positives and three mixed families passed. Generic fitted-edge support then reduced this to one aligned antialiased diamond (`probe2.log`). Removing the shape-independent global IoU cutoff while preserving the one-pixel edge band and unchanged interior constraints was proposed to resolve it. The final independent corpus passes the corresponding positive controls.
2. **A coarse color sample excluded valid checker fills.** The initial square checker candidate was absent. The implementation removed the pre-filter after it also bypassed outline-only ambiguity protection. The independent checker probe then retained both objects; only actual boundary/core and click support determine permission.
3. **Repeated selected holes became a new family.** Six ordinary gray references + six same-fill objects with large white holes + two normal positives yielded eight proposals across all eight tested shape families (`repeated-selected-before.log`); all eight passed pre-click. The repeated hole was omitted from the learned occupied core, so reported holes were zero. Learning now rejects enclosed-hole templates without filling them. Probe 2 preserved the two positive objects and rejected the six marked objects; hole-only references are explicitly unsupported rather than treated as a success case.
4. **Repeated connected pairs became one large seat.** Six standalone references + six narrow-bridge pairs (12 true objects) produced only six proposals for seven shapes (`repeated-bridge-before.log`). Large-family score/NMS suppressed the smaller independently supported silhouettes. A decomposition check has been added for two disjoint, separately repeated shapes whose outside boundaries remain visible. The final independent corpus passes the corresponding positive controls.
5. **An open white cut teaches fragments as seats.** Closed-hole rejection does not address a three-pixel white stripe connected to the exterior. Six whole gray references + six striped objects + two positives produced 14 proposals, two on each striped object (`open-white-before.log`); every proposal passed pre-click. All eight tested shapes reproduced it. The final localized whole/fragment competition policy holds these proposals, and all eight shapes pass. The same image can mean lettering, a selected mark, or two genuine smaller seats. Global small-family removal or disallowing all target-colored references would break separate positive contracts; parent rejected the latter because an all-available map is a core entry scenario. The independent mixed-small-family fixture verifies that distant ordinary small seats remain clickable. The integration reviewer additionally checks all-available maps and three-piece splits; no universal semantic disambiguation is claimed.
6. **Large component storage.** Initial component traversal retained every foreground pixel coordinate, including components too large to become references. The implementation now completes traversal while stopping coordinate storage beyond reference bounds; raw bounds/target totals remain available for bounded merged-component searches. Read review confirms the intended distinction. No worst-case memory measurement has been claimed. The bounded coordinate-storage correction was independently read; resource limits are not whole-app latency guarantees.

7. **Changed global interpretation bypassed local pre-click proof.** A single permitted small object was unchanged while a new neighboring fragment made full current extraction ambiguous. The old local pre-click check still returned true (`temporal-competition-before.log`). The final context proof binds observed ROI RGBA including alpha, image geometry, full vision settings, target color, and tolerance. On change, the same current acquired frame is fully re-extracted once, and the old bounds/shape must remain permitted; the original point still needs opaque matching support. There is no re-capture loop. The negative test now passes; integration positives cover unrelated inside/outside ROI changes and zone-prefixed IDs. Screen changes after acquisition and before OS delivery remain outside this guarantee.
8. **A bounded number of expensive positions still caused a long stall.** A 400×400 thin border with 100×100 repeated references admits about 90,000 search positions under the existing cap. Most positions are empty, but full-template checking took 1,457,875 µs in an optimized intermediate run. The final lazy foreground integral computes an exact rectangular upper bound on possible occupied template pixels and skips only impossible fits. The same synthetic input took 3,263 µs in the final single-thread run. These are single samples, not a timing guarantee. A connected 3×3 grid activates the shortcut and retains all nine hits with full-frame, nonzero ROI origin, and padded-stride layouts.

## Positive and negative coverage

Required positives include circle, square, rectangle, rounded rectangle, diamond, ellipse, two rotations, small 7px squares; dark-line/cross splits; narrow bridges and one-pixel gaps; diagonal neighbors; mixed shapes and large/small families; multicolor/checker fills; AA/subpixel and dark backgrounds; size changes; padded scanline layouts. Partial opacity, excluded pixels, and cropped objects must not poison a fully observed neighboring object. Broad merges and incomplete reference families are separately marked ambiguous; such negative controls do not count as shape coverage.

## Code and integration review

The production identity path retains exact-point fallback, uses checked whole-silhouette evidence for shape membership and overlap, and preserves legacy bbox policy when no object proof exists. Slanted bbox adjacency uses actual row-wise silhouette gaps rather than forced spacing. Process-local proof is skipped by serde, and missing proof is refused by object pre-click validation. The integration reviewer additionally exercises the actual Engine, original queued proof, current scene pixels, count on/off, retained/failed neighbors, repaint, pause/resume, refresh, and cancelled stale acknowledgements. Those are event-level tests, not Worker/OS execution.

## Limits and reproducibility

An identical raster can represent one dumbbell-shaped seat or two seats joined by a narrow line. Pixels alone cannot resolve that semantic difference. A site count read is a separate client-visible cardinality signal, not server ownership or an automatic undo proof. Hollow/lettered/selected patterns require explicit ambiguity treatment; neither color nor shape generally reveals selection state.

All new support code belongs under the source tree so source manifests include it. Old verification artifacts are not overwritten. `probe1-source.json` and per-run logs identify early experiments. Probe 2 records its source hashes; an initial flat snapshot basename collision affected the two files named `seat_object_shapes.rs`, so nested preserved copies are authoritative only where `copy-status.json` says true. This intermediate capture limitation is disclosed; final test evidence is tied to a complete nested source snapshot and before/after hashes.
