# 검색 조건 변경 후 재시도 검토

2026-10-22 사용자가 정상적으로 좌석 범위를 다시 지정해도 이전 좌석 기록과 다르다는 경고가 반복된다고 보고했습니다.
기준은 배포한 0.5.11 소스이며 [기준 해시](source-baseline.json)와 [제한한 현장 기록](user-report.json)을 보존했습니다.
사용자 설정·실제 창·입력·기존 배포물은 변경하지 않습니다. 이번 소스 교정은 아직 앱으로 빌드하지 않았습니다.

## 확인한 원인

실행 기록에 같은 오류가 15회 있었습니다. 이전 run 12의 마지막 영상 분석은 ROI `(3,331,1968,1353)`, 허용값 30이었고,
다시 저장한 값은 ROI `(0,434,2063,1345)`, 허용값 29였습니다. 관측된 창 크기는 양쪽 모두 3024×1784, 배율 2였습니다.
최초 오류의 정확한 비교 실패 항목은 당시 로그가 구분하지 않아 확정하지 않습니다.

`start_guarded`는 창·배율 외에도 VisionConfig 전체, 색상·허용값·판정 정책을 전부 비교하고 모든 실패에 같은 문구를 표시했습니다.
실패한 시작은 과거 RestartContext를 남기고, Save/F8은 현재 Engine만 Idle로 갱신했습니다. 다음 시작이 다시 과거 조건과 비교하므로 정상적인 재채집 후에도 보류가 반복될 수 있었습니다.
경고를 없애려고 과거 이력을 삭제하면 이미 전달한 좌석을 다시 클릭해 선택을 취소할 위험이 있어 이력은 유지합니다.

## 교정 범위

- 같은 연결 창·픽셀 크기·배율과 같은 수량/외곽 판정 정책에서는 ROI·제외 영역·색상·허용값·성분 크기 필터를 바꿀 수 있습니다. 기존 클릭점·외곽·전달/실패 이력·수량 증거는 유지하고 새 관측으로 후보를 검증합니다.
- F2/F5와 F9가 같은 필터 변경 계약을 사용합니다. 취소표 이동 방식 비교는 기존처럼 취소표 재시작에서 이전 활성 구역이 있을 때 적용합니다.
- 중간 실패·저장 뒤 F4를 눌러도 보존 이력이 사라지지 않게 합니다. 반복 중지에서는 알려진 미해결 오류창의 문맥을 우선합니다.
- 창 변경, 크기·배율 미확인/변경, 선택 수량 판정 변경, 외곽 판정 변경, 해당 취소표 이동 변경은 실제 원인별 메시지와 로그 코드로 구분합니다. 두 판정 옵션은 이전/현재 켜짐·꺼짐도 표시합니다.
- 보존 checkpoint가 있는 복구에서는 실패 뒤 원래 좌표계를 새 설정의 좌표계로 덮어쓰지 않습니다. 반복 F9·자동 복귀·재개도 그 원본 좌표계 증거를 확인합니다. 수동 재개는 수량/외곽 판정 정책도 다시 검사하며, 새 캡처·창 전환 뒤에는 후속 명령의 소유권을 재확인합니다.

## 검증과 한계

구현·독립·반대 검토를 분리합니다. 독립 검사는 기존 코드의 필터 변경 거절과 저장 뒤 F4 이력 손실을 각각 실패로 재현했습니다.
실제 Engine, 공유 런타임 helper, VisualRecovery를 검사하며, 실제 Worker·OS·브라우저를 실행한 검사로 표현하지 않습니다.
최종 검사·소스 해시와 각 리뷰의 연결은 `final-manifest.json`에 기록합니다.

같은 창·같은 크기라고 공연·좌석 화면 내용까지 같다는 뜻은 아닙니다. 사이트에서 직접 선택을 해제하거나 같은 창에서 새 공연으로 이동하면 보존 이력과 실제 선택이 달라질 수 있습니다.
특히 수량 확인 OFF에서 이전 완료 기록이 목표 매수에 도달해 있으면 새 관측 후 완료 버튼만 다시 전달할 수 있습니다. 이 의미상의 새 세션 문제를 이번 필터 변경 보류 수정으로 해결했다고 주장하지 않습니다.
전체 지연·물리 입력·로그인 예매·Windows 동작은 미검증이며, 원래 이미지 기반 좌석 인식의 한계는 유지합니다.
