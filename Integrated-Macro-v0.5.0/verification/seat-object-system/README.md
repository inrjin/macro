# 좌석 객체와 사이트 수량 검증

이번 변경은 소스와 정적 입력을 검증한 미배포 실험 기능입니다. 실제 브라우저 입력이나 Windows 실행을 확인한 결과가 아닙니다. 기존 0.5.9 앱·ZIP과 두 `AGENTS.md`는 보존합니다.

## 기능과 지원 범위

두 기능 모두 기본 OFF이며 서로 독립적입니다.

| 옵션 | 동작 | 확인되지 않은 범위 |
| --- | --- | --- |
| 원형 좌석 외곽으로 구분 | 등록 색 주변의 반복되는 원형 외곽을 이용해 내부 색 조각을 합치거나 얇게 연결된 두 원을 분리합니다. 클릭 직전에 전체 후보를 다시 검사합니다. | 사각형·다각형 등 비원형, 충분한 반복 외곽이 없는 화면, 모양이 같은 비좌석 장식, 선택 전후가 거의 같은 표시 |
| NOL 선택 좌석 수 확인 | 화면 전체에서 `선택 좌석` 문구와 연결된 수량을 찾습니다. 위치를 고정하지 않고 좌석 모양에도 의존하지 않습니다. 목표 수량을 확인한 뒤 완료를 허용합니다. | 지원하지 않는 글꼴·배경·줄바꿈, 일부 픽셀이 미관측된 캡처, 실제 공연의 숫자 없는 0석 화면 |

원형 옵션 OFF에서는 기존 색상 탐색을 그대로 사용합니다. 이 경로의 비원형 좌석 합침·분할까지 해결한 것은 아닙니다. 원형 옵션에서 후보가 없다는 안내는 실제 좌석이 없다는 확정이 아닙니다.

수량이 읽히지 않으면 0으로 바꾸지 않습니다. 숫자 없는 0석은 제목·명시적인 좌석 없음 문구·선택 완료 버튼이 구분되는 동일 패널에 있어야 합니다. 이 판정은 제한된 시각적 배치 검사이며 HTML 계층을 복원하지 않습니다. 왼쪽·오른쪽 배치는 지원 사례로 검사했지만 모든 공연 구성을 지원한다고 주장하지 않습니다.

## 실행과 입력 보호

첫 수량에는 사용자가 이미 선택한 좌석도 포함합니다. 클릭 전달 후에는 예상한 정확한 1석 증가를 기다립니다. 수량이 그대로이거나 줄거나 예상보다 많이 늘면 추가 좌석·완료를 보류하고 계속 관측합니다. 명시적으로 귀속 가능한 선점 실패는 해당 시도만 제외하며, 원인이 모호한 감소를 되돌리려고 같은 자리를 다시 누르지 않습니다.

관측은 실행·요청·입력 시점과 연결됩니다. 관측한 숫자와 무관하게 시간이 지났다는 이유만으로 추가 클릭하지 않습니다. 수량을 읽어 발급한 좌석 클릭·완료·취소표 새로고침·구역 이동에는 해당 실행과 동작에 묶인 근거를 요구합니다.

입력 직전에 얻은 화면에서 수량 근거가 달라지면 미전달 취소합니다. 근거 영역 밖만 바뀌었어도 전체 판독을 한 번 다시 수행합니다. 다른 패널의 모순 문구나 두 번째 제목을 놓치는 결함을 재현해 수정했습니다. 타이머만 변한 화면은 같은 수량으로 재판독되면 진행하며, 화면 전체가 멈출 때까지 무한 재캡처하지 않습니다. 판독 이후 OS 입력 사이에 사이트가 바뀌는 경쟁 상태 자체를 없앤 것은 아닙니다.

수량 확인 모드에서 수동 실패 보고는 아직 누르지 않은 다음 후보가 아니라 실제 전달한 좌석에 귀속합니다. 수동 선택 확인 버튼은 제공하지 않고 사이트 수량을 다시 읽습니다. 이 모드의 가려짐 자동 복귀는 좌석 탐색·충돌·완료 단계에만 추가하며 입장·캡챠·구역 이동의 기존 정책은 유지합니다. 해당 회귀는 실제 Engine과 생산 helper를 사용했으며 두 Worker 호출부는 별도 소스 검토로 확인했습니다.

화면 픽셀이 같으면 순수 판독 결과만 재사용합니다. 캡처 유효성·입력 이후 시점·현재 요청·중지 신호는 매번 검사하고 클릭 허용 근거도 새로 발급합니다. 캐시가 과거 동작의 허용을 되살리지 않습니다.

## 검증 근거

- [원형 객체 분석](vision/README.md): 합침·분할·가까운 이웃·투명 픽셀·선택 표시·실제 Engine 연결 검사와 반례. 제공된 이미지에서 사용 가능 원형 2개를 찾고 선택 표시 3개를 제외했습니다. 원형 객체와 사이트 좌석 번호의 동일성을 증명한 결과는 아닙니다.
- [수량 Engine 검토](engine/review.md): 기존 선택 유지, 지연된 증가, 불일치, 완료, 재시작, 오래된 요청과 옵션 OFF 동작.
- [문자·배치 독립 검토](reader-review/README.md): 생산 템플릿을 복사하지 않은 108개 렌더 사례. 필수 인식 41개, 대안 글꼴·표시 37개, 거절 사례 30개를 구분합니다. 읽기 실패를 인식 성공에 합산하지 않습니다. 픽셀 누락·잘못된 버퍼 검사는 별도 테스트입니다.
- [런타임·UI 검토](runtime-review.md): 입력 직전 재확인, 정적 macOS 캡처 관측, 새로고침·구역 이동, 캐시 및 실제 렌더 문자 반례. OS 입력은 실행하지 않았습니다.
- [최적화 판독 측정](reader-optimized-final.json): 제공된 3024×1608 이미지에서 3석 판독, 독립 프로세스 5회 **148–170ms**. 캡처·브라우저·OS 전달을 제외한 한 이미지의 측정입니다. 제목 글꼴은 같은 이미지에서 가져온 재현 자료이며 숫자 3은 템플릿으로 사용하지 않았습니다.

템플릿은 `generate-count-templates.swift`와 분리한 `heading-reference.json`으로 재생성합니다. 참조에는 제목의 글자 모양만 있고 화면 좌표·좌석 목록·캡챠 이미지는 없습니다. 합성 자료와 중간 실패 기록은 보존해 최종 통과와 구분합니다.

최종 전체 검사에서 Rust **367개 통과·0개 실패·수동 검사 2개 제외**, JavaScript **150개 통과·0개 실패**를 확인했습니다. 전체 검사 전후 소스 122개와 JavaScript 검사 대상 54개의 해시가 일치합니다. 로그는 `workspace-final.log`, `javascript-final.log`, 결과·소스 연결은 `final-checks.json`, `source-final.json`에 기록합니다. 구현자 외 두 검토자가 실제 소스와 호출 경로를 읽고 반례에 대한 수정도 재검토했습니다.

## 남는 한계

사이트의 선택 수 표시는 서버의 최종 선점·결제 성공을 증명하지 않습니다. 사용자의 동시 선택·해제, 낙관적인 사이트 표시, 늦은 오류는 현재 클릭과 정확히 연결되지 않을 수 있습니다. 이때 보류는 오클릭 방지이며 무조건 진행된다는 보장이 아닙니다.

실제 예매창에서 0→1→2 전환, 좌석 실패 안내창, 비원형 배치, macOS·Windows 입력과 화면 배율을 함께 검증해야 합니다. 기존 배포본에 이번 코드가 들어갔다거나 실전 준비가 끝났다고 선언하지 않습니다.
