# 우선순위별 통합 검증

2026-10-21 · 대상 소스 0.5.8 · 기존 취소표 집중 감사의 후속 검사

## 검증 범위

담당 에이전트를 런타임·엔진·독립 반례 검토로 나누고, 주 담당이 결과와 별도의 사이트 선택 상태를 비교했다. 우선순위별 판정은 아래 순서로 정리한다. 독립 시나리오 준비와 교차검토는 병행했다.

격리된 headless Chromium으로 로컬 페이지를 열려 했으나 macOS `bootstrap_check_in ... Permission denied (1100)`로 브라우저가 종료됐다. 우회하거나 사용자 권한을 바꾸지 않았다. 따라서 이번 결과는 **합성 RGBA → 실제 인식기 → 실제 엔진 → 공유 런타임 판정 함수**의 검사이며, 전체 Worker/브라우저/OS 입력 실험은 아니다. [브라우저 실행 시도 기록](browser-attempt.json).

테스트가 통과했다는 말은 아래 **정상 대조군과 알려진 한계의 재현이 예상대로 완료됐다**는 뜻이다. 재현된 한계를 해결한 것으로 합산하지 않는다.

## P1. 구역 전환과 이전 화면

이전 구역의 캐시 이미지가 원본 구역 이동의 대기 시간 뒤 새 구역 후보로 쓰이는 것을 실제 vision·Engine과 클릭 직전 공유 함수까지 연결해 재현했다. 클릭 직전 두 번째 캡처가 새 이미지를 반환하면 사라진 좌석·투명한 픽셀·크기 변경을 거절하지만, 그 캡처도 unchanged라면 이전 이미지의 후보가 통과한다.

새 이미지 번호와 입력 이후 시각만으로도 사이트의 구역 전환 완료를 보장할 수 없다. 로딩 표시만 바뀐 이미지에 옛 좌석이 남을 수 있다. 반대로 같은 이미지가 정상 목적지인 경우 엄격한 새 이미지 조건은 가상 시간 1시간까지 탐색을 막는 반례를 보였다.

**판정: 미해결 구조 한계.** 화면 전환 정책을 임의로 바꾸지 않았다. 네이티브 관측의 최신성과 사이트 화면의 의미는 별개이며, 이를 보장하려면 추가 식별 신호가 필요하다.

[엔진 검사](p1-engine/README.md), [런타임 검사 및 동작 동일 함수 분리](p1-runtime/README.md), [독립 검토](reviewer/P1-review.md).

## P2. 늦은 선점 실패창

실제 `VisualRecovery`가 합성 이미지에서 발생시킨 신호만 엔진에 전달했다. 검사 코드가 실패한 좌석 ID를 미리 알려주지 않았다.

- 정상 대조군: 두 번째 시도의 실패창을 감지하고 Esc를 전달한다. 창이 그대로인 동안에는 닫힘으로 판단하지 않으며, 복원된 이미지 뒤 첫 시도를 유지하고 세 번째 후보로 진행한다.
- 반례: 첫 요청의 실패창이 두 번째 클릭 뒤 나타나면 감시 중인 최신 시도인 두 번째 좌석에 귀속된다. 실제로 실패한 첫 시도는 선택 추정에 남는다.
- 완료 버튼 전달 뒤에는 감시를 끝내므로 그 후의 알림은 처리하지 않는다. 이는 기존에 정한 완료 범위이며 이번에 확장하지 않았다.

**판정: 정상 복구 경로는 통과, 늦은 알림의 귀속은 보장할 수 없음.** 특정 사이트가 실제로 이 순서를 보인다고 주장하지 않으며, 추가 대기나 사이트 선택 목록 수집을 임의로 도입하지 않았다. [재현과 한계](p2-engine/README.md).

## P3. 빈 화면에서 잠깐 나타나는 좌석

새로고침 OFF의 실제 Engine에 합성 이미지를 공급하고 출현 시점을 바꿨다. 관측 시점에 존재한 좌석은 모두 후보와 클릭 제안으로 이어졌다. 관측 사이에만 존재한 좌석은 놓쳤다.

가정한 검사 간격은 20ms이며, 출현 위상 20개를 열거했다. 1/4/8/16/40ms 동안 나타나는 좌석은 각각 1/4/8/16/20개 위상에서 관측됐다. **이는 현재 앱의 실측 주기·반응 속도·예매 성공 확률이 아니다.** 실제 캡처/입력 지연은 미검증이다. [측정 조건과 원본 결과](reviewer/vision-findings.md).

## P4. 내부 새로고침의 지연·무응답

실제 공유 캡처/입력 이후 프레임 조건/색상 검사와 Engine을 연결했다. 10초의 가상 시간 동안 캡처가 갱신되지 않아도 등록된 버튼은 설정한 1초 간격으로 10회만 전달되고, 이전 프레임의 좌석 클릭은 0회였다. 탐색 단계는 유지됐고 ACK만으로 세대가 바뀌지 않았다. OFF에서는 갱신 입력 없이 탐색을 유지했다.

새 이미지 번호라도 촬영 시각이 최신 갱신 입력보다 이전이면 거절했다. 이후 조건을 만족하는 새 좌석 이미지가 관측되면 후보 처리를 재개했다. 단, 최신 입력 뒤에 도착한 이미지가 어느 사이트 요청의 응답인지까지 식별할 수는 없다.

**판정: 설정 간격·대기·재개 계약 통과, 사이트 응답의 의미와 실제 캡처 시점은 별도 한계.** 갱신 정책은 바꾸지 않았다. [검사 기록](p4-runtime/production-harness.log).

## P5. 좌석과 비좌석의 구분

현재의 색상·연결 영역 방식에서 다음을 재현했다.

- ROI 안의 동일색·동일크기 범례도 후보가 되며, 위쪽에 있으면 실제 좌석보다 먼저 선택될 수 있다. 범례를 ROI 밖으로 빼거나 제외 영역에 넣은 대조군에서는 제외됐다.
- 가장자리로 붙은 두 좌석은 한 후보로 합쳐진다. 1~2픽셀 영역은 현재 최소 3픽셀 조건에서 제외된다.
- 큰 비좌석 영역을 ROI 경계로 작게 잘라 놓으면 최대 크기 제한을 통과할 수 있다.
- 부분 투명 픽셀도 추출기는 허용하지만, 런타임 클릭 직전 `color_at` 검사는 alpha 250 미만을 거절한다. 추출된 후보 수를 실제 오클릭 수로 해석하면 안 된다.

**판정: 색상 방식의 누락·오인 조건 확인.** 최소 크기를 낮추거나 모양 조건을 강제하는 변경은 다른 좌석에서 오탐·누락을 늘릴 수 있어 적용하지 않았다. [조건별 증거](reviewer/vision-findings.md).

## P6. 선택 추정 수와 사이트 상태

엔진과 독립된 사이트 선택 집합을 만들고 실제 이미지 추출 후보의 클릭 좌표로 사이트를 갱신했다. 양쪽 모두 수락하는 대조군은 2석/2석이었다. 첫 클릭을 사이트가 조용히 무시하거나 두 번째 클릭 때 이전 선택을 지우면, **앱 추정 2석·사이트 선택 1석인데 완료 동작이 제안됐다.**

**판정: 사용자가 선택한 낙관적 집계 정책의 한계 재현.** 사이트 선택 상태를 엔진에 몰래 알려주지 않았으며, 확인 대기나 새 연동 기능도 추가하지 않았다. 실제 완료 버튼 전달·서버 응답은 이 검사의 범위 밖이다. [결과](p6-selection/README.md), [독립 오라클 검토](reviewer/P6-oracle-review.md).

## P7. 중단·복구와 좌표

실제 Engine·vision·VisualRecovery를 연결한 13개 조합에서 입력 취소와 기존 시도 보존 계약이 통과했다. 미전달 Esc만 재개 뒤 다시 요청하고, 전달된 Esc는 중복 요청하지 않았다. 첫/둘째 좌석·완료·Esc 대기 및 완료 전달 이후의 Stop에서는 늦은 ACK나 Resume로 실행이 되살아나지 않았다.

이는 런타임이 미전달 입력을 `ActionCancelled`로 먼저 알리는 계약을 따르는 검사다. 실제 OS 큐·창 가림 판정은 모사하지 않았다. [중단 행렬](p7-engine/README.md).

소수 배율에서는 실제 결함을 재현하고 수정했다. `scale=1.75`에서 인식된 픽셀 `(61,5)`를 논리 좌표로 나눈 뒤 다시 픽셀로 환산하면 부동소수점 반올림으로 `(60,5)`가 되어, 클릭 직전 검사에서 배경을 읽고 좌석 후보를 취소했다. 1배·2배 대조군에서는 이 반례가 발생하지 않았다. 사용자의 과거 Mac 실패 전체를 이 원인으로 단정하지 않는다.

수정은 이미지에서 얻은 정수 좌석·구역 후보에 한정한다. 색상 검사와 Mac 입력·가림 복구가 같은 픽셀 중심을 사용한다. 일반 예매 진입·내부 갱신·완료·원본 구역 좌표와 가져온 소수점 좌표의 변환 방식은 유지한다.

교차검토에서 Windows 입력 어댑터가 이미 픽셀 중심 보정을 하는 점을 발견했다. 동일한 보정을 앞단에서 더하면 좌표가 바뀌므로, Windows의 입력은 기존 픽셀 인덱스를 유지하고 색상 검사는 그 픽셀의 중심을 읽는다. Windows 분기는 순수 변환/정규화 수식으로 검사했으며 실제 Windows 빌드·OS 입력 성공으로 간주하지 않는다.

**판정: 소수 배율의 이웃 픽셀 오판 수정, 중단·재개 계약 통과.** [수정 전 실패](p7-runtime-pixels/before-fix.log), [수정 후 검사](p7-runtime-pixels/after-fix.log).

## 최종 검증과 배포 범위

동결한 소스에서 `npm test` **141개**, `cargo test --workspace --offline --locked` **270개**, 합계 **411개 통과**, 실패·건너뜀 0이다. 별도의 P2 시나리오 3개와 P7 중단 행렬 13개는 이 수에 합산하지 않았다. 알려진 한계를 재현하는 검사도 포함되므로 통과 수를 해결된 문제 수로 해석하면 안 된다.

운영 소스 변경은 `src-tauri/src/runtime.rs`의 기존 판단을 공유 함수로 분리한 부분과 이미지 후보 픽셀 변환 수정에 한정된다. 새 core 검사 파일 3개를 추가했다. production 엔진·native 드라이버·UI·설정 스키마·버전은 변경하지 않았다. 동결한 소스 101개의 해시가 전체 검사 후 그대로이고, 루트 `AGENTS.md`, 기존 v0.5.8 앱 실행 파일·ZIP도 이전 해시와 일치했다.

실제 OS·브라우저 입력, 실사이트별 전환·좌석 선택, 장시간 실행 성능은 이번 결과로 확인하지 않았다. 선택 성공 판단이나 추가 대기 정책은 임의로 변경하지 않았으며 배포 패키지도 만들지 않았다.
