# 좌석 객체 기억 방식: 엔진 읽기 검토

소스 읽기와 에이전트 반론 교환만 수행했다. 생산 코드·테스트 수정, 테스트 실행, 빌드, 실사이트 입력은 하지 않았다. 아래 사례는 소스 조건에서 도출한 설계 반례이며 실제 공연 화면에서 발생했다고 확정하지 않는다.

## 현재 구현

- `vision.rs`는 지정 RGB와 허용 오차에 맞는 픽셀을 4방향 연결 성분으로 묶는다. 기본적인 색상 객체 분리는 이미 한다. 좌석에는 불투명한 2×2 일치 패치 조건도 적용한다.
- 실제 픽셀 목록은 후보에 보관하지 않는다. `CandidateGeometry`에는 외접 사각형과 픽셀 수만 남긴다.
- 엔진은 전달된 원래 후보를 active_region과 함께 기억한다. 선택 표시 때문에 줄어든 후속 조각으로 원래 영역을 덮어쓰지 않는다.
- `same_seat`는 ① 실제 클릭점 동일 ② 어느 한 사각형이 상대 클릭점을 포함 ③ 작은 사각형 면적의 75% 이상 겹침 중 하나면 동일 좌석으로 판단한다. **②는 75% 조건 없이 즉시 참**이다. 일정 반경을 띄우거나 옆 좌석을 일정 간격씩 건너뛰는 로직은 없다.
- 연석의 0.75×작은 폭 간격 기준은 그룹 우선순위다. 간격이 크거나 행이 맞지 않으면 그룹으로 우선하지 않을 뿐, 유효 후보를 제거하지 않는다. 분리 좌석 fallback은 그대로다.

## 실제 이웃을 제외할 수 있는 조건

1. **사각형 내부의 빈 공간:** ㄱ/U/고리 모양 원래 성분의 bbox 안에 독립된 이웃 객체가 있을 때, 실제 색상 픽셀 교집합이 없어도 그 이웃 클릭점이 bbox 안이라 제외될 수 있다. 예를 들어 10×10 bbox의 두꺼운 위·왼쪽 막대와, 우하단 빈 곳의 별도 3×3 성분은 색상 성분으로는 분리되지만 bbox 포함 조건은 참이다.
2. **얽힌 비정형 윤곽:** 별개 성분의 외접 사각형이 많이 겹치면 75% 조건도 실제 픽셀 겹침을 과대평가할 수 있다.
3. **화면 내부 이동:** 스크롤/지도 이동 후 다른 좌석이 예전 좌표에 놓이면 exact-point 및 bbox 기억 모두 객체 의미를 잃는다. 픽셀 mask도 위치 정합 없이 비교하면 같은 한계를 가진다. 현재 좌표와 지도 맥락이 유지된다는 전제가 필요하다.

반대로, 사각형이 겹치지 않는 두 객체는 가까이 있어도 위 조건으로 합쳐지지 않는다. 경계만 닿는 bbox도 실제 점을 공유하지 않고 교집합 면적이 0이면 합쳐지지 않는다. 동일 색 픽셀이 실제로 이어져 한 연결 성분이 되는 경우는 엔진 bbox 비교 이전의 별도 분할 문제다.

## 객체 mask/윤곽을 도입한다면

권장 방향은 원래 연결 성분의 **실제 픽셀 mask와 객체 라벨**을 기억하는 것이다. 원래 component의 행별 픽셀 구간(RLE) 등으로 저장하면 bbox를 빠른 비교 대상 제한에 쓰고, 실제 교집합을 두 번째 판단으로 사용할 수 있다. 선택된 객체 수와 현재 실패 제외 대상만 장기 보관하면 전체 화면 복사를 요구하지 않는다. 성능 수치는 측정 전이므로 확정하지 않는다.

- 선택 전의 성분 라벨은 이웃 구분의 보조 증거로 유지한다. 다만 처음부터 다른 성분이었다는 이유만으로 영구적으로 별개 좌석이라고 판정하지 않는다. 한 좌석도 글자·흰 선으로 여러 색상 성분으로 나뉠 수 있다. 중복 방지 mask의 무조건적인 확장·병합도 피한다.
- 클릭 후 원래 객체에서 남은 색상 조각은 원래 mask와 대응시켜 같은 객체의 다른 렌더링으로 취급한다. 원래 mask를 작은 조각으로 교체하지 않는다.
- 선택 후 색상이 전부 바뀌더라도 기존 전달 기록을 없애지 않는다. 색상 mask가 보이지 않는 것은 선택 성공/실패 확인이 아니다.
- ACK 전 취소는 mark를 만들지 않는다. 유지된 mark는 Pause/Resume 및 검색/새로고침에서 유지한다. 실패 mark만 현재 취소표 재탐색 주기 또는 명시 갱신의 기존 정책에 따라 해제한다. 새 실행·지도/좌표 맥락 교체는 별도 reset이다.

## mask만으로 해결되지 않는 반례

reviewer가 제시한 반례: 녹색의 두꺼운 고리 좌석이 선택 후 회색 고리와 중앙의 녹색 2×2 표식으로 바뀌면 원래 녹색 mask와 새 mask의 교집합이 0이다. 실제로는 같은 좌석인데 단순 mask 교집합만 보면 다른 객체가 된다. 고리 내부를 채워 막으면, 선택 전부터 그 빈 공간에 있던 독립 객체까지 합치는 반대 문제가 생긴다.

따라서 **원래 색상 mask**, **배경 경계로 추정한 전체 객체 영역**, **사이트의 의미상 좌석**은 서로 구분해야 한다. 같은 binary mask의 contour만 따는 것은 새로운 객체 의미를 만들지 않는다. 배경 추정·윤곽 내부 채움·closing/dilation에는 숫자·그라데이션·그림자·붙은 도형에 대한 새로운 가정이 필요하다.

추가 반례로, 처음부터 글자·흰 선 때문에 한 좌석이 두 개의 색상 성분으로 나뉘면 두 성분의 bbox가 겹치지 않을 수 있다. 초기 라벨이 다르다는 이유로 비교를 영구 면제하면 같은 좌석을 두 번 클릭할 수 있다. 현재 bbox 방식도 이 경우까지 해결하지 않는다.

현실적인 후속 검증은 원래 성분 라벨, 공유 외곽·배경 경계, 국소 전후 변화를 함께 살피는 방식이다. 성분 라벨은 보조 증거이며 좌석 객체 ID와 동일하지 않다. 이를 자동 대기나 서버 성공 검사로 확장할 필요는 없다. 다만 임의 좌석 시스템에서 완전한 의미상 객체 식별을 보장한다고 표현해서는 안 된다.

## 수정 전 확인할 대조군

- 한 픽셀의 배경 간격으로 분리된 작은 두 좌석: 둘 다 선택 가능.
- ㄱ/U형 bbox 빈 공간의 독립 객체: 한쪽 선택 후 다른 쪽 유지.
- 원래 solid 좌석이 선택 후 축소/분리: 동일 객체 재클릭 차단.
- 고리→중앙 표식 변경과, 고리 내부에 원래 있던 별도 객체를 서로 구별.
- 처음부터 숫자·흰 선으로 나뉜 한 좌석과, 실제로 분리된 이웃 좌석을 구별.
- 경계 색 번짐으로 두 객체가 연결/분리되는 경우: 객체 merge/split 처리를 명시.
- 실패 재시도 시 해당 객체만 해제하고, 유지된 다른 객체는 보호.
- 내부 지도 이동/배율 변경 후 잘못된 원래 mask 적용 방지.

vision 담당과 reviewer 모두 bbox보다 원래 mask 보존이 정밀한 최소 개선 방향이라는 데 동의했다. 동시에 contour 내부 채움이나 단순 색상 교집합 하나만으로 범용 좌석 식별이 완성되지는 않는다는 반례를 확인했다.
