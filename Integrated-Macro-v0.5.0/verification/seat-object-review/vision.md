# 좌석 객체 인식: 읽기 전용 설계 검토

이 문서는 현재 소스 확인과 설계 비교만 기록한다. 새 코드, 테스트, 빌드, 실화면 조작은 실행하지 않았다.

## 현재 구현

- `crates/macro-core/src/vision.rs:39`: 지정한 색과 R/G/B 각 채널 차이가 허용값 이내인 픽셀을 찾는다. 배경색을 학습하거나 화면 전체 색상 군집을 추정하지 않는다.
- `vision.rs:133`: ROI·제외 영역·색상·불투명도를 적용한 이진 마스크를 만든다. 좌석은 alpha ≥ 250, 구역용 일반 추출은 기존 alpha ≠ 0 정책이다.
- `vision.rs:160`, `vision.rs:189`: 상하좌우 4방향으로 이어진 픽셀을 한 연결성분으로 묶는다. 지정색이 아닌 간격으로 분리된 가까운 좌석은 별개 성분이다. 대각선만 접한 픽셀도 별개다. 이는 이미 기본적인 색상 기반 객체 분할이다.
- `vision.rs:146`, `vision.rs:212`: 좌석은 같은 색의 불투명한 2×2가 있어야 하며, 그 패치를 구성하는 픽셀 중 성분 중심에 가까운 곳을 고른다. 실제 좌석/활성 상태를 확인하는 조건은 아니다.
- `vision.rs:230`, `crates/macro-core/src/model.rs:249`: 후보에는 원래 전체 연결성분의 최소 축 정렬 사각형과 픽셀 수를 저장한다. 추출 중 실제 픽셀 목록은 있지만 후보에는 마스크/윤곽/내부 빈 공간 정보를 남기지 않는다.
- `crates/macro-core/src/engine.rs:1089`, `crates/macro-core/src/seat_selection.rs:17`: 전달된 후보를 기억하고 새 후보와 비교한다. 중복 제외는 같은 점, 사각형의 클릭점 포함 또는 작은 사각형 면적의 75% 이상 겹침이다. 고정 반경만큼 이웃 좌석을 띄우는 방식은 아니다.

따라서 ‘원래 영역’은 사이트가 알려준 좌석 전체 영역이 아니라, 클릭 전 캡처에서 **지정색으로 연결되어 있던 한 덩어리를 감싼 사각형**이다. L/U형 성분처럼 사각형 내부에 넓은 빈 공간이 있으면 그 안의 별개 성분을 같은 좌석으로 오인할 수 있다.

## 개선 선택지와 한계

| 방식 | 얻는 것 | 비용·한계 |
| --- | --- | --- |
| 기존 연결성분 유지 + 원래 실제 픽셀 마스크 보존 | 사각형 속 빈 공간과 실제 색상 영역 구분. 선택 표시로 분리된 조각을 원래 성분과 비교. 가까운 이웃에 일괄 거리 제한 불필요. | 전달된 몇 개 성분의 로컬 마스크와 겹침 연산 필요. 초기 색상 영역 밖으로 바뀐 테두리나 위치 이동에는 교집합이 없을 수 있다. |
| 같은 이진 마스크의 윤곽 추적 | 외곽·구멍을 표현하거나 압축할 수 있다. | 같은 마스크에서 얻는 정보이므로 좌석 의미나 선택 성공 정보가 늘지는 않는다. 빈 공간 채우기·팽창은 이웃을 합칠 수 있다. |
| 주변 배경색 추정 + 다색 경계 기반 전체 객체 분할 | 숫자·체크 표시로 색이 끊겨도 좌석 전체를 묶을 가능성. | 배경 그라데이션, 그림자, 테두리, 맞닿은 좌석, 범례에 대한 새 규칙 필요. 추가 영상 처리와 실제 여러 화면 검증이 필요하며 성능 수치는 미측정이다. |

최소 검토안은 현재 연결성분을 버리지 않고 원래 실제 마스크를 남겨 중복 비교를 정밀하게 만드는 것이다. 배경 기반 전체 객체 인식은 별도 확장으로 평가해야 한다. 어느 방식도 RGB 화면만으로 서버의 선점 성공이나 실제 좌석 번호를 보장하지 않는다.

독립 반박에서 구분한 반례: 두꺼운 색상 ring이 선택 뒤 회색 ring과 원래 빈 중앙의 같은 색 표식으로 바뀌면 동일 좌석이어도 색 마스크 교집합은 0일 수 있다. 윤곽 내부를 채우면 이를 연결할 수 있지만, ring/U형 내부에 실제 별개 객체가 있는 경우는 잘못 합친다. 8방향 연결로 확대하는 방법도 모서리만 접한 별개 좌석을 합칠 수 있다. 이들은 새 실험 결과가 아니라 설계상 필요한 대조 조건이다.
