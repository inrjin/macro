# 선택 좌석 수 전체 점검 — 미배포 소스

2026-10-21. 수량 판독, 실제 Engine 상태 전환, 입력 직전 근거 검사, 취소표 호출 순서,
결과 캐시와 사용자 안내를 나누어 점검했습니다. 구현자와 독립·반례 검토자가 서로 소스와
재현 결과를 확인했습니다. 기존 배포 앱·ZIP·AGENTS.md와 이전 검증 기록은 보존합니다.

## 확인한 결함과 변경

1. **숫자 표현을 잘라 읽음.** 두 자리 수의 뒤 숫자, 부호, 소수점, 작은 후속 숫자가 후보
   필터에서 빠져 `12`, `1.5` 등을 `1`로 확정했습니다. 이제 단일 숫자 주변에 추가 표시가
   없는지 함께 검사합니다. 원본 판독기와 실제 Engine을 연결해 목표 1석의 완료 동작이
   잘못 발급되는 것도 재현했습니다. [원본 재현](runtime-original-reproduction.log).
2. **다른 설명 속 제목을 현재 선택 수로 오인함.** `최대 선택 좌석`, `미선택 좌석`의
   부분 일치를 재현했고 제목 앞의 독립된 경계를 검사합니다. 다른 글꼴의 두 번째 제목을
   놓치는 반례에는 해당 글꼴의 제목 자료를 보충했습니다. 임의의 문장 의미나 모든 글꼴을
   읽는 일반 OCR로 확장한 것은 아닙니다.
3. **정상 배율에서 제목을 놓침.** 23px 크기의 소수점 위치 렌더에서 제목을 찾는 시작점과
   글자 경계가 어긋났습니다. 제한된 위치 보정과 실제 연결된 글자 경계 보정으로 대응하며,
   판독 점수 기준을 일괄 낮추지 않았습니다.
4. **0석을 확정하는 과정에서 작은·옅은 추가 표시를 무시함.** 선택 없음 안내가 있어도
   숫자 영역과 패널 본문에 모순되는 내용이 남아 있으면 보류하도록 검사합니다. 옅은 패널
   경계 인식과 본문의 숫자 검사는 별개로 처리합니다. 제목 경계 보정은 0석 경로에서만
   최대 한 픽셀로 제한하고, 추가 픽셀이 안쪽 획보다 더 진해지면 별도 표시로 보류합니다.
   제목·안내문 주변의 빈 여백 전체를 면제하지 않고 연결된 얇은 글자 가장자리만 허용합니다.
   작은·옅은 모순 표시 26개를 차단하면서 정상 0석 배율·위치·색상 대조군 26개를 읽었습니다.
   임의의 글자 의미를 판별한다는 보장은 아니며 상세 반례와 지원 한계는 독립 보고서에 기록합니다.
5. **새 좌석을 읽기 전에 취소표 구역을 넘김.** 수량 이벤트가 이전 빈 후보 목록으로
   새로고침·화살표·구역 클릭을 발급했습니다. 같은 프레임의 후보를 먼저 반영하도록 순서를
   바꿨습니다. 현재 후보 분석 실패·영역 미지정은 이전 후보에 대한 입력을 허용하지 않습니다.
   이미 목표 수에 도달한 완료와 첫 구역 진입·확인된 미전달 구역 클릭 재시도는 예외를 유지합니다.
6. **판독 실패 원인을 알 수 없음.** 문구 미검출·중복, 문구 주변의 모호함, 숫자 표현,
   선택 없음 안내 영역 등을 상태 메시지로 구분합니다. 같은 판독에서 원인을 얻고 결과와
   함께 캐시하므로 진단 때문에 한 번 더 OCR하지 않습니다.
7. **숫자와 빈 좌석 안내가 동시에 있어도 수량을 확정함.** 추가 32개 대조 중 24개에서
   정상적인 글자 크기의 빈 안내를 놓쳐 `2`를 확정했습니다. 실제 판독기·캐시·Engine을
   연결한 검사에서도 목표 2석의 `CompleteSelection`이 발급됐습니다.
   [수정 전 실행 경로 재현](runtime-empty-contradiction-before.log).
   원인은 긴 문구의 위치·폭 추정 실패와 글꼴·배율 자료 부족을 포함합니다. 숫자 승인 전
   실제 문자행 경계를 비교하는 별도 모순 검사를 추가했습니다. 이 추가 검사는 숫자를 보류할
   수만 있고 0석 승인을 허용하지 않습니다. 연속된 문자 성분의 부분 구간도 검사해 근접 UI에
   문구가 합쳐지는 문제를 막고, 크기와 이진 픽셀이 완전히 같은 반복 무늬는 판독 결과를
   재사용합니다. hash가 같다는 이유만으로 재사용하지 않고 실제 바이트도 비교합니다.
   32개 모순, 가까운·먼 UI와 문구 없는 대조 6개, 밀집 좌석 1,800개 화면을 통과했습니다.
   숫자 영역 밖에 모순 안내가 새로 나타나면 이미 허용된 동작도 입력 직전 재판독에서 보류합니다.

## 검토 방법과 증거

- [판독 구현과 수정 기록](implementation/README.md): 생성기에 의한 재현 자료와 실제 코드 변경.
- [독립 문자·배치·성능 검토](adversarial/README.md): 생산 템플릿을 복사하지 않은 렌더,
  부분 가림·다른 문구·복수 제목·0석 문맥의 양성 및 음성 대조군.
- [Engine·실제 호출 경로 검토](engine/review.md): 기존 선택 유지, 지연된 복수 실패, Esc,
  완료 취소, 갱신·구역 이동 취소, 일시정지, 재시작, Unknown 반복과 옵션 OFF.

숫자를 못 읽는 경우를 0으로 바꾸지 않습니다. ACK는 입력 전달만 의미하며, 다음 입력은
사이트 수량의 예상 변화와 새로운 관측 허용을 요구합니다. Engine 검사에서는 별도 선택
목록을 가진 모의 사이트로 실제 수량을 관리했습니다. 이미지 검사에서 정상 숫자를 모두
거절하는 것은 성공으로 세지 않습니다. 실패·중간 결과와 최종 결과는 구분해 보존합니다.

실제 Worker 전체나 OS 입력을 실행한 검사는 아닙니다. 생산 순수 함수·실제 판독기·실제
Engine을 연결한 회귀와 Worker 호출부의 소스 검토를 구분합니다. 원본 재현의 Engine에는
이번에 추가한 읽기 전용 정책 조회가 있을 수 있으나 기존 상태 전환 로직은 바뀌지 않았습니다.

최종 명령, 통과 수, 검사 전후 소스·재현 자료 해시, 배포물 보존 결과는
[final-checks.json](final-checks.json)에 기록합니다.

최종 고정 소스에서 **Rust 425개 통과·실패 0·수동 검사 5개 제외, JavaScript 150개 통과**입니다.
독립 판독 검사는 9개 통과했고 별도로 최적화된 성능 검사 1개를 실행했습니다. 실제 제공된
3석 이미지도 3석으로 판독했습니다. 검사 전후 소스 131파일과 입력 자료·생성기 484파일의
해시가 동일합니다. [전체 Rust](rust-final.log), [JavaScript](javascript-final.log),
[실제 이미지 회귀](actual-count3-final.log).

독립 원본 이미지 182개와 숫자 부분 가림 112개를 검사합니다. 반드시 읽어야 하는 양성,
잘못된 입력을 보류해야 하는 음성, 정확한 수량 또는 보류만 허용하는 미지원 글꼴 탐색을
분리했습니다. 182개를 전부 인식했다는 뜻이 아닙니다. 별도의 구현자 재현과 기존 회귀도
검사하며, 진단 API는 기존 판독 결과와 동일한 분석에서 이유만 추가합니다.
후속 모순 32개와 근접 UI 6개는 이 182개에 섞지 않고 별도 원본·실패 로그를 보존합니다.
총 원본 220개에서 필수 양성 43개와 필수 거절 71개가 모두 조건을 만족했습니다.
지원 범위 탐색 106개는 84개 정답·22개 보류이며, 그 보류를 인식 성공으로 세지 않습니다.
부분 가림 112개는 36개 정답·76개 보류·잘못된 수량 확정 0개였습니다.

## 남은 범위와 성능

위치가 고정된 판독기는 아니지만 지원하는 문구·글꼴·배치에는 제한이 있습니다. 인식할 수
없는 글꼴의 다른 제목이 화면에 없다고 일반적으로 증명하지는 못합니다. 이번 작은 숫자
반례에는 원래 제목 경계 밖의 추가 픽셀이 실제로 있었으므로, 서로 같은 이미지여서 구별할 수
없는 경우로 분류하지 않습니다. 근사 글자 인식의 한계와 사이트 자체의 모순된 표시는 별개입니다.
읽기 실패·예상치 않은 증감·클릭 후 무변화는 보류를 유지하며 성공이나 실패로 추정하지 않습니다.
문자행 모순 검사에는 처리량·패턴 저장 상한이 있습니다. 너무 복잡한 화면에서 상한을 넘으면
모순이 없다고 간주하지 않고 수량을 보류하므로, 모든 화면에서 진행을 보장하지 않습니다.

변한 화면은 전체 판독이 필요하므로 이 옵션에는 지연이 있습니다. 정적 픽셀의 판독 결과는
캐시하지만 새로운 요청·입력 이후 시점·중지·클릭 직전 검사는 생략하지 않습니다. 이번 수정은
수량을 결정하기 전에 현재 좌석 후보도 관측합니다. 개별 판독 벤치는 화면 캡처·좌석 분석·
Worker 대기·OS 입력·사이트 반응을 포함하지 않으며 실전 지연을 보장하지 않습니다.

첫 정확성 통과 소스의 전체 Rust 검사는 421개 통과, 수동 검사 5개 제외였습니다. 이 시점의
소스·자료·로그는 `checkpoint-before-search-scope/`에 보존합니다. 독립 합성 큰 화면의
판독 시간이 기존 약 190ms에서 약 290–310ms로 늘어난 것을 확인해 검색 범위의 불필요한
확장 여부를 별도로 검사했습니다. 이 과정에서 위 24개 모순 누락을 추가로 발견했으므로
421개 통과 시점을 최종 준비 완료로 해석하면 안 됩니다. 성능 변경은 판독 조건이나 전체 화면의 중복 제목 검사를
생략하는 방법으로 해결하지 않습니다. 최종 결과는 독립 보고서와 최종 검사 기록을 따릅니다.

최종 독립 측정은 3024×1608 정적 합성 화면에서 각 3회입니다. 숫자 3과 좌석 지도가 있는
화면은 **242.5–253.2ms**, 0석 패널과 지도는 **248.5–260.5ms**였습니다. 중간 약 300ms보다
줄었지만 같은 숫자 3 장면의 초기 189.4–191.1ms보다 여전히 약 27–34% 느립니다. 실제 제공된
3석 이미지의 단일 판독은 258ms였습니다. [최종 독립 성능](adversarial/final-adopted-performance.log).

제공된 실제 이미지는 3석 화면의 회귀 대조군이며 해당 이미지의 제목 모양은 이전에 인식
자료로 사용됐습니다. 독립된 새 사이트 일반화 검증으로 세지 않습니다. 실제 0→1→2 전환,
0석 화면, 다른 공연과 Windows 실행·배포 빌드는 이번에 실행하지 않았습니다.
