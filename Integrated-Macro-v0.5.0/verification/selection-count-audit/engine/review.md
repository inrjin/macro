## Scenarios

1. Normal, Seats, and Cancellation: one preexisting selection plus A; queued B is proven undelivered and cancelled. Unknown, late B ACK, duplicate count serial, and Tick cannot count B. A fresh unchanged site total permits a new B attempt, then observed target total alone permits completion.
2. A queued completion is cancelled. Unknown, an actual decrease, late completion ACK, and context pause/resume cannot complete. Only a new matching total authorizes a different completion action.
3. B has already been reflected in the total when its explicit failure cancels queued completion. A remains selected; B is rejected; only C replaces it.
4. A and B are already reflected while C is outstanding. Two explicit late failures share one Esc, preserve C, require count 1 rather than count 0, and allow only the next D input. The old Esc ACK cannot remove queued D.
5. Esc is proven undelivered, then Pause/Resume occurs. Only Esc is retried; its successful ACK becomes the new freshness boundary. Retained A survives and C fills the missing seat.
6. Internal refresh and both legacy navigation variants: cancellation rotates the request, old count/ACK are inert, and an unexpected positive total cannot authorize navigation as if it were zero. A second run for each variant starts with one actual preexisting selection and checks that repeated empty-map polls never refresh or navigate away from it.
7. 150 repeated Unknown, unchanged-zero, old-request and Tick cycles preserve one outstanding click. The actual later increment releases B, and final target releases completion.
8. Stop/new Start discards prior attempts and requests. Count OFF still uses the existing optimistic flow.

9. Same-frame ordering: after an empty map, a newly acquired frame now contains A. Feeding its count before its candidates issues Refresh, ArrowUp, or a second-region click in all three cancellation variants. The caller then returns because the phase is no longer Seats, so A is never observed. Feeding A first and then the identical zero count issues `seat:a` instead. This is an actual Engine reproduction of the runtime source ordering, not whole-Worker execution.

10. The Engine query requires current candidates only for count-enabled Seats below target, except deliberate initial/retried legacy navigation. All three run modes, OFF, Idle/Completing/Completed, already-satisfied/excess totals, cancelled navigation retry, and initial positive selection are compared.

## Confirmed caller defect

Before correction, `observe_frame` fed a readable count before extracting that same frame's candidates. `observe_selection_count` calls `tick`, which may consume the previously observed empty map and issue refresh/navigation. Runtime's phase-not-Seats early return then skips the new map. Trigger: count ON, cancellation mode with navigation/internal refresh, prior empty map, and an eligible refresh/navigation interval when a new seat appears. The parent owns the fix: reflect current candidates before granting the count event's one-step input permit, preserving initial target-already-satisfied completion without requiring seat ROI. Extraction failure must not leave stale map state authorized. Engine transition and count mutation logic are unchanged. The parent added the runtime correction after this reproduction.

## Actual caller review

`observe_frame` reads only the current Engine request and checks current run/action receipt freshness. It attaches count proof only to a protected pending action issued by that same observation. `execute_actions` reacquires the latest frame for seats, completion, refresh and legacy navigation; a changed or unreadable proof becomes `ActionCancelled` before native input. `feed` invalidates proof on interruption and pending-action replacement. Engine permission is one-event-only, so later Candidate/Tick events do not spend a saved count authorization.

The final read-only pass found no additional Engine-state blocker beyond the corrected runtime ordering issue above. Independent rendered fixtures also confirmed numeric-prefix and false-zero reader defects; the reader corrections and their negative/positive controls are recorded below. Correct gating cannot compensate for an incorrect accepted image count, so these were treated as input-authorization defects rather than merely cosmetic recognition errors.

## Correction review

`selection_count_needs_seat_observation` is a side-effect-free Engine query: feature ON, phase Seats, count below target, and not initial/retried legacy navigation. Independent reviewer read the implementation and tenth regression; no additional Engine blocker was found.

The parent extracted `observe_candidates_on_frame`. Count-mode Seats now installs the same acquired frame's candidates before `SelectionCountObserved`. Successful extraction of an empty list is current evidence, not failure. Missing ROI or failed extraction produces Unavailable when a map is required; stale prior candidates cannot receive a permit. Already-satisfied totals and deliberate initial/retried legacy navigation retain their calibration-independent routes. Count OFF remains on its original lower scan path. The count proof still belongs only to an action granted by that same count event, with current-frame pre-input checks unchanged. This was an actual source/caller review; runtime helper regressions are recorded in `../runtime-after-order-fix.log` (17 passed, one timing check ignored); the final parent-owned workspace result is connected below. Object extraction on every successful count poll has a cost and is not a whole-app latency claim.

Reader review also checked `isolated_count`: signs, punctuation and small trailing components are rejected from the original binary mask rather than dropped by the digit-size filter, and the validation band is covered by returned proof evidence. Nearby unrelated UI inside that band or clipped band edges may be unsupported. A short blank boundary left of the heading is not general recognition of the label's complete semantic context. Reader corpus generation and image-oracle assertions are independently reviewed by their designated owners.

## Final reader and caller review

The zero path now checks an originally matched heading separately from normal digit recognition. `empty_heading_bounds` permits at most one pixel of connected boundary correction, and every added raw RGB pixel must be no darker in any channel than its adjacent original glyph pixel. This rejects the reproduced attached black numeral rather than describing its distinct pixels as an information-theoretic impossibility. Uniform ink direction separately rejects differently colored attached text. Neither change raises the general glyph-recognition thresholds or alters the ordinary numeric path.

The panel's label margin exempts only a directly adjacent one-pixel fringe; it no longer follows a transitive flood into an unrelated tiny character. Other content must match the measured panel background exactly, so faint wrapped numbers cannot disappear under the edge-color tolerance. This deliberately rejects unsupported textured or explanatory layouts instead of inventing zero. The lane/button proof remains a limited layout contract, not complete semantic ownership of every possible webpage panel.

The preserved intermediate `../implementation/after-zero-monotonic-fringe.log` records six independent-reader tests, three numeric-completeness tests and five preexisting reader tests passing (one optional reader timing test ignored). The added 26 tiny/faint contradictory-zero cases all return Unknown, and 26 normal-zero size/position/fractional-render controls remain readable. The preexisting 105 rendered cases also pass. These are rendered fixtures, not a claim that every overlapping glyph, font or real-site state is recognized.

`CountDiagnosis` performs the same single analysis as the compatibility `read_selection_count` wrapper. Runtime caches the result and diagnostic together by frame dimensions/stride/full RGBA digest. Unknown still issues the request-scoped `SelectionCountUnavailable`; its issue only improves the status message. No missing result becomes zero. Input proof remains bound to the current run/action and the accepted frame evidence, with a full reader recheck if the latest acquired image changes outside the local evidence area. Map extraction failure cannot spend a cached count permission; current successful empty extraction is valid map evidence. Already-satisfied totals and initial legacy-navigation exceptions retain their earlier contracts. The cache contains image-analysis results, not reusable Engine authorization.

The negative-line implementation was then independently reviewed: `(top, bottom, seed_height)` exactly keys the candidate row/filter/join inputs; bounded contiguous sub-runs retain an empty phrase when neighboring UI extends the maximal row. The width early exit uses the maximum possible row height, so a later taller sub-run is not incorrectly pruned. Rejected comparisons are reused only for equal width, height and complete binary pixels; `HashSet` checks byte equality rather than trusting a hash alone. The 2,000,000 row/window, 128 MiB sampled-area, 4 MiB stored-pattern and 1,024 unique-pattern limits return NumericContext/Unknown before numeric authorization. These are finite-work policies, not a promised wall-clock latency. The extra references carry the distinct `empty_negative` label and cannot be consumed by the positive zero/completion label paths.

The final runtime regression source first requires a number-only two-seat frame to be accepted, then introduces an independently rendered empty label outside the unchanged numeric crop. `evidence.matches` remains true, but the production full-frame input recheck rejects the action. The test also runs the actual reader/cache/evidence helpers into a target-two Engine and checks no premature CompleteSelection; the uncontradicted two-seat positive must still complete. The latter initial-authorization portion passed in the earlier one-test log; the newly added temporal assertions passed in the final workspace run. It does not instantiate the full Worker or deliver OS input.

The final isolated three-sample copy comparison measured count-plus-map median 283.9 to 243.5 ms and zero-panel-plus-map 298.6 to 253.0 ms. The many-component no-label case moved from 157.4 to 170.5 ms, so no across-the-board speed claim is made. These optimized static reader calls are not app/capture/input latency; the earlier approximately 190 ms checkpoint also remains separate.

## Limits

Count-only observation cannot establish which physical seat changed or attribute a late failure dialog. No-increment, unexplained decrease/jump, or unreadable totals can keep the engine observing indefinitely; that is a documented hold rather than demonstrated successful progress. The harness uses correct explicit delivery/conflict events and does not test native races, capture provenance, text matching, actual site acceptance, or OS execution. No release/app build, physical keyboard/mouse input, live browser booking, macOS application execution or Windows execution was performed in this audit. Shared Rust component tests are not Windows runtime verification. Feature OFF retains the prior path; the new status diagnostics do not establish site acceptance. Historical release artifacts, AGENTS files and user profiles were not modified by this agent.
