# 0.4.0 좌표 버전 검토 결과

## 구현과 수정

- Windows와 Mac을 독립 실행 버전으로 분리했습니다. Mac은 SwiftUI 네이티브 `.app`, Windows는 공식 AutoHotkey 런타임이 포함된 실행 폴더입니다.
- 좌표·색·범위 기반 클릭, 추가 클릭 목록, 취소표 1구역/2구역 모드, 시각 API를 이용한 예약 클릭, 캡챠 직접 입력 후 재개를 포함했습니다.
- 외부 시작 메시지/브라우저 브리지 코드를 제거했습니다. 현재 버전에는 확장 프로그램이 없습니다.
- 취소표 전용 탐색 제한을 추가했습니다. 기본값은 1시간입니다.
- 경합 안내의 두 표식 확인 → 닫기 → 실패한 좌석 제외 → 다른 후보 재시도를 구현했습니다. 서로 다른 두 표식 좌표가 필요합니다.
- 여러 좌석 선택 중 실패 좌석을 특정할 수 없으면 중지합니다. 화면 색만으로 서버 확보 성공을 확정하지 않습니다.
- 가격 화면 준비 표식을 확인한 뒤에만 추가 클릭을 진행하도록 검증합니다.
- Mac은 클릭 전 캡처를 그대로 사용해 선택 성공이나 화면 전환으로 판정하지 않도록 프레임 검사를 추가했습니다. 정지 화면을 나타내는 idle 캡처와 꺼진 화면을 구분합니다.
- Windows 클릭 오프셋은 기본 0이며, 오프셋을 사용하더라도 범위와 색이 맞는 지점인지 확인합니다.
- 새 예매 창에서는 캡챠 대기를 유지하며 F7로 창을 다시 연결하고 F6으로 재개할 수 있습니다.
- API 설정 변경 시 기존 시각 보정을 거절합니다. ISO 응답의 소수점 자릿수와 HTTP Date의 초 단위 해상도를 오차 표시에 반영합니다.

## 확인한 범위

- macOS 13 이상 대상 Apple Silicon/Intel 빌드 생성.
- Apple Silicon에서 실제 프로덕션 상태 전이 코드를 사용하는 로컬 검사 **12개 묶음 통과**.
  - 한국시간·잘못된 날짜·JSON 시각·ISO 시간대와 해상도·단조 시계 계산.
  - 픽셀 검색, 제외 좌석, 범위 검사, 후속 클릭 설정 검증.
  - 구역 클릭 뒤 새 화면 대기.
  - 경합 안내 닫기와 다른 좌석 선택.
  - 클릭 후 새 화면 확인과 선택 색 되돌림 처리.
  - 취소표 두 구역 전환, 한 구역 지속 대기, 탐색 시간 초과.
  - 가격 화면 확인 후 순차 추가 클릭.
  - 캡챠 이후 준비 표식의 변화 확인과 긴급 중지.
  - 예약 버튼 단 한 번 클릭과 API 변경 시 기존 보정 거절.
- Mac 앱 ad-hoc 서명 무결성 검사, 두 아키텍처 포함 여부, ZIP 파일 무결성과 실행 권한 검사.
- Windows 소스 포함 파일·UTF-8 BOM·브리지 제거 여부 검사. 동봉 런타임 및 대응 소스 ZIP의 SHA-256을 기존 공식 배포 기록과 대조했습니다.

로컬 검사는 합성 화면과 입력 기록 함수를 사용합니다. 실제 브라우저를 클릭하거나 실제 좌석을 선택하지 않습니다.

## 아직 확인하지 못한 범위

- **Windows 실제 실행, AutoHotkey 문법 실행 검사, PowerShell 시각 조회 실행.** Windows 패키지에 클릭 없는 `Self-Test.cmd` 16개 검사를 포함했으나 이번 Mac 환경에서는 실행하지 못했습니다.
- **Mac 실제 UI 조작·화면 캡처 권한·클릭 권한의 전체 흐름.** 화면 확인 도구가 `native pipe startup failed`로 연결되지 않았습니다.
- **실제 Intel Mac 실행.** Intel 바이너리는 빌드했고 실기 동작은 확인하지 않았습니다.
- **이 좌표 버전으로 실제 사이트에서 처음부터 끝까지 예매하는 흐름, 실전 경합, 실제 서버 시각 API 조회.** 이전 사이트 분석 결과가 현재 배포본의 실전 통과를 의미하지 않습니다.
- **0.01초 이내 확보 또는 다른 사용자보다 빠른 성공.** 측정하거나 보증하지 않았습니다.

경합 자동 대응과 준비 표식 감지는 실제 화면에서 표식을 채집하고 옵션을 켜야 동작합니다. 공연마다 달라지는 구역 지도, 창 크기와 좌석 배치는 직접 설정해야 합니다. API 주소도 확인된 값을 사용자가 등록해야 합니다.
