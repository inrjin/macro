# P6: 선택 추정과 독립된 사이트 상태 비교

`crates/macro-core/tests/priority_selection_oracle.rs`는 좌석 3개를 그리는 합성 사이트를 사용한다. 사이트는 자신의 사각형으로 클릭 위치를 판정하며, 자체 선택 집합을 바탕으로 다음 RGBA 이미지를 만든다. 실제 `vision::extract_candidates`와 `Engine`에 이미지로부터 나온 후보 및 입력 전달 ACK만 제공한다. 사이트의 선택 집합이나 실패 좌석 ID를 엔진에 알려주지 않는다.

| 사이트의 클릭 처리 | 앱의 선택 추정 | 사이트의 실제 선택 | 완료 버튼 동작 제안 |
| --- | --- | --- | --- |
| 두 클릭 모두 수락 | 2 | 2 | 발생 |
| 첫 클릭을 조용히 무시 | 2 | 1 | 발생 |
| 두 번째 클릭 시 이전 선택 해제 | 2 | 1 | 발생 |

이는 사용자가 선택한 ‘오류창 없이 전달한 클릭은 선택으로 추정’ 정책의 한계를 재현한다. 현재 정책으로 사이트가 조용히 무시한 클릭이나 이전 선택의 해제를 확정적으로 알 수 없다. 이 검사에 맞추려고 새로운 선택 확인 대기나 사이트 데이터 수집을 추가하지 않았다.

검사 3개 통과는 정상 대조군과 위 두 반례가 재현됐다는 뜻이다. 브라우저, 런타임의 클릭 직전 검사, 시각적 안내창 복구, 실제 OS 입력은 포함하지 않는다. 완료는 엔진이 동작을 제안한 지점에서 멈추며 실제 완료 버튼의 성공을 검사하지 않는다. 별도 담당자가 오라클 독립성을 검토했다: [검토 기록](../reviewer/P6-oracle-review.md).

프로젝트 루트에서 기존 `.build-tools` Rust 환경을 적용한 뒤 실행:

```sh
cargo test -p macro-core --test priority_selection_oracle --offline --locked -- --nocapture
```

원본 실행 결과는 [results.txt](results.txt)에 보존했다.
