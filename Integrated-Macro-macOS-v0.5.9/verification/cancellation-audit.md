# 취소표 집중 감사

2026-10-21 · 소스 버전 0.5.8 · 배포 빌드 없음

## 범위와 검토 방식

주 담당과 에이전트 3명이 취소표 UI·설정 병합, 엔진의 반복 탐색·좌석 유지, 런타임의 실행 옵션·화면 수집을 나눠 검토했다. 재현 → 수정 → 다른 담당자의 반례 검토 → 전체 회귀 검사를 진행했다. 실제 앱을 실행하거나 브라우저에 입력하지 않았으며 사용자 설정·권한을 변경하지 않았다.

## 재현하여 수정한 문제

| 문제 | 변경 후 동작 |
| --- | --- |
| 화살표 이동에서 두 구역 클릭으로 바꿨지만 좌표가 없으면 이전 화살표 방식이 실행됨 | 명시적으로 두 구역을 선택한 경우 시작/F2에서 유효한 좌표 두 개를 확인한다. 저장과 F8 지정은 계속 가능하다. 오류는 실제 UI의 ‘원본 · 첫 번째 구역’, ‘원본 · 두 번째 구역’을 지칭한다. |
| 내부 새로고침을 켰던 설정이 원본 구역 이동에 남아 F6 대기 또는 구역 순환 중단을 유발함 | 실행용 설정에서 현재 선택한 방식에 해당하는 옵션만 적용한다. 저장된 옵션은 보존한다. 최초 정적 화면 탐색도 같은 실행용 설정을 사용한다. |
| 일반 예매의 구역 우선순위 옵션이 취소표 구역 이동을 가로챔 | 취소표 실행에서는 일반 예매용 구역 우선순위를 적용하지 않는다. 일반 예매의 저장 설정은 보존한다. |
| 2구역 F8 응답이 도착할 때 1구역의 미저장 색상 편집이 사라짐 | 고정된 두 구역 설정을 구역별로 병합한다. RGB·좌표·사각형 값의 원자적 병합 및 다른 배열의 기존 정책은 유지한다. |
| 구형 두 구역 프로필에서 모드를 왕복하면 좌표가 사라지거나 ‘미지정’으로 표시됨 | 기존 이동 좌표를 보존하고 표시한다. 범위 표시도 실제 구역별 범위/공통 범위 적용 상태와 일치시킨다. |

새 설정의 기본값은 ‘한 구역 · 현재 좌석 계속 탐색’이다. 기존에 저장한 화살표/두 구역 선택은 유지한다. 내부 새로고침은 취소표에서 사용 ON, 내부 버튼 방식, 버튼 좌표 등록이 모두 충족될 때만 실행한다. 버튼이 없으면 탐색을 계속하고 준비 상태에 ‘새로고침 버튼 미지정 · 탐색만 진행합니다’를 표시한다.

## 반복 동작 검증

- 실제 UI 코드와 제어된 IPC로 4가지 방식 × 새로고침 ON/OFF × 좌표 유무 × 시작 버튼/F2의 32개 조합을 확인했다. 공통/구역 색상, 완료 좌표, F8 중 편집 보존도 검사했다.
- 실제 `macro_core::Engine`에 합성 이벤트를 주어 좌석 하나를 유지하며 다른 좌석 실패를 1,000회 반복했다. 새로고침 ON/OFF 각각 검사하고 취소된 Esc 뒤 일시정지·재개 및 오래된 응답도 포함했다.
- 빈 좌석 탐색 1,000회, 내부 버튼 갱신 1,000회 뒤 좌석 출현, 두 구역 교대 1,000회에서 추가 상태 오류를 발견하지 못했다.
- 실패 후보를 다음 탐색 주기에 재시도하는 기존 정책은 유지했다. 검색 주기의 재시도와 실제 사이트 새로고침은 별개다.
- 최종 동결 소스에서 `npm test`: **141 통과**, `cargo test --workspace --offline --locked`: **245 통과**, 실패·건너뜀 0. 위 별도 실험은 386개 수에 중복 합산하지 않았다.

## 남은 문제: 원본 방식의 구역 전환과 이전 화면

원본의 시간 기반 구역 이동은 지정한 지연 뒤 새 구역이 준비됐다고 가정한다. 지연이 끝나도 수집된 이미지가 이전 구역이면 그 이미지에서 좌석 후보를 만들 수 있다는 반례를 확인했다.

반대로 ‘입력 이후 새 이미지 번호와 촬영 시각이 나와야 한다’는 조건만 추가하면, 화살표가 화면을 바꾸지 않거나 이미 열린 구역을 누를 때 정적인 화면에서 계속 대기하는 반례가 생긴다. 이 엄격한 조건은 적용하지 않았다. 기존 강화 경로의 F6 확인도 이번 감사에서 제거하지 않았다.

해결에는 픽셀이 같더라도 입력 이후의 관측인지 확인할 수 있는 수집 경로가 필요하다. macOS의 idle 알림만으로 항상 새 관측이 온다고 보장할 수 없으므로, 별도 최신 스냅샷 수집과 지연 측정·실제 창 검증이 후속 과제다. 이번 소스 수정만으로 이 문제가 해결됐다고 판단하면 안 된다.

실제 티켓 사이트의 좌석 인식·확보 성공, 설치된 앱의 입력/권한, Windows 실행은 이번 검사로 확인하지 않았다. 시각적 알림 감지는 의미 판독이 아니므로 늦게 뜬 알림의 좌석 귀속도 완전히 보장하지 않는다.
